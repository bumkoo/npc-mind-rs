## 1. 벤치마크 목적

Step 4.1에서 임베딩(bge-m3) 기반 감정 분류가 71.7% 한계에 도달했다. 존대말 바이어스, 간접 적의 인식 불가 등 구조적 문제를 확인하고, LLM 직접 판정 방식으로 전환하여 정확도를 검증한다.

### 1.1 임베딩 방식의 한계 (Step 4.1 요약)

| 모델 | 전략 | warmth | coldness | neutral | 전체 |
|------|------|:------:|:--------:|:-------:|:----:|
| bge-m3 | B/20 (최고) | 100% | 70% | 45% | **71.7%** |

- coldness 실패: 존대말("~하겠소") → warmth로 오분류
- neutral 실패: 정보 전달을 warmth로 과대 분류
- 구조적 원인: 임베딩은 표면 문체를 감정으로 오인

### 1.2 LLM 판정 가설

LLM은 대화 맥락과 의도를 이해하므로, 존대말 바이어스를 극복하고 85%+ 달성 가능.

## 2. Phase A: 단일 대사 판정

### 2.1 설계

60개 테스트 대사(warmth 20, coldness 20, neutral 20)를 3턴 대화로 래핑하여 LLM이 NPC 감정을 JSON으로 판정.

```
플레이어: "{대사별 맞춤 질문}"
NPC:      "{테스트 대사}"
플레이어: "{대사별 맞춤 반응}"

→ LLM 판정: {"sentiment":"warmth|coldness|neutral", "score":-3~+3, "reason":"..."}
```

**v1.0→v1.1 핵심 변경**: 고정 질문("객잔이 있소?") → 대사별 맥락 맞춤 질문 60개 작성.  
v1.0에서 warmth 70% 원인이 맥락 불일치였음 (LLM이 대화 논리까지 평가하여 "엉뚱한 답 = 적대"로 해석).

### 2.2 결과

```
  Phase A v1.0 (고정 질문)     Phase A v1.1 (맞춤 질문)
  ─────────────────────       ─────────────────────
  warmth   70.0%              warmth  100.0%  ★
  coldness 100.0%             coldness 100.0%  ★
  neutral   85.0%             neutral  100.0%  ★
  전체      85.0%             전체     100.0%  ★
  JSON 파싱 100.0%            JSON 파싱 98.3% (1건: score를 문자열로 반환)
```

### 2.3 임베딩 vs LLM 최종 비교

```
                bge-m3(B/20)   LLM v1.0    LLM v1.1
  warmth        100.0%         70.0%       100.0%
  coldness       70.0%        100.0%       100.0%
  neutral        45.0%         85.0%       100.0%
  전체           71.7%         85.0%       100.0%
  처리시간/건    7.40ms        1541ms       1408ms
```

**결론**: LLM v1.1 — 60개 전건 정답. 임베딩 실패 17건 전부 복구.

### 2.4 핵심 교훈

1. **맥락이 전부**: 동일 모델에서 질문만 바꿔 70%→100% 달성
2. **LLM이 "너무 똑똑함"**: 대화 논리 일관성까지 평가 — 테스트 설계 시 맥락 일치 필수
3. **score 파서 보강 필요**: LLM이 score를 문자열("-2")로 반환하는 경우 존재 → i64+str 이중 파싱 적용

### 4.3 Phase B 핵심 교훈: 판정 주기 재고

Phase B 실행 결과, 3턴마다 판정하는 초기 설계에 대한 중요한 교훈을 얻었다.

**응답 시간: 턴 수에 거의 영향 없음**

```
  입력 규모     평균 응답
  CP1 (3턴):  4348ms  (B01 콜드스타트 제외)
  CP2 (6턴):  4323ms
  CP3 (9턴):  4680ms

  차이: ~300ms (무시할 수준)
```

원인: 입력 토큰 증가는 GPU 병렬 처리로 비용이 작고, 출력은 동일하게 JSON 한 줄(~45토큰)이므로 생성 시간이 지배적.

**판정 주기: 3턴 → 9~12턴 권장**

```
  3턴마다 판정              9~12턴마다 판정
  ├─ LLM 호출: 3회/9턴        ├─ LLM 호출: 1회/9턴 (1/3 감소)
  ├─ 응답 시간: 거의 동일      ├─ 응답 시간: 거의 동일
  ├─ 맥락: 3턴분              ├─ 맥락: 9~12턴분 (더 풍부)
  └─ 감정 명확성: 대사가 명확해야 함  └─ 감정 명확성: 대화 흐름으로 판단 가능
```

근거:
- Phase B 시나리오 10개 중, 각 구간 대사가 감정이 너무 뚨렸하여 3턴씩 독립 전송해도 유사한 결과가 나올 가능성이 높음
- 9~12턴 누적이면 대화 흐름 전체를 보고 판단하므로, 모호한 대사도 맥락으로 구분 가능
- 게임 체감상 9~12턴이 자연스러운 "장면 전환" 단위
- 30턴 이상 장기 대화 시에는 "이전 요약 + 최근 9~12턴" 하이브리드 방식 필요

참고: 초기 3턴 설계는 경험적 선택이었으며, 학술적 근거가 아닌 무협 대화 리듬(인사→본론→반응 = 2~3턴) 기반이었다.

## 5. 판정 프롬프트 상세

### 5.1 시스템 프롬프트 (Phase A/B 공통)

```
너는 무협 소설의 대화를 분석하는 감정 평가관이다.
주어진 대화에서 NPC가 플레이어에게 보이는 **현재** 감정을 판정하라.
대화의 흐름에서 가장 최근 NPC 발언을 중심으로 판정하되, 이전 맥락도 고려하라.

반드시 다음 JSON 형식으로만 응답하라. JSON 외의 텍스트는 절대 금지:
{"sentiment":"warmth 또는 coldness 또는 neutral","score":-3에서 3 사이 정수,"reason":"판정 근거 한 문장"}

sentiment 기준:
- warmth: 호의, 감사, 신뢰, 격려, 연민, 환영, 친밀감
- coldness: 적의, 분노, 경멸, 거부, 불신, 실망, 무시
- neutral: 단순 정보 전달, 일상 대화, 감정 없는 안내, 사무적 태도

score 기준:
+3: 강한 호의/애정  +2: 명확한 호감  +1: 약한 호감
 0: 중립
-1: 약한 반감  -2: 명확한 적의  -3: 강한 적대

중요: 무협체 존대말("~하오", "~하겠소")은 문체일 뿐 감정이 아니다. 내용의 의도를 판단하라.
```

### 5.2 유저 메시지 — Phase A (3턴 고정)

```
다음은 NPC와 플레이어의 대화이다. NPC의 감정을 판정하라.

플레이어: "{대사별 맞춤 질문}"
NPC: "{테스트 대사}"
플레이어: "{대사별 맞춤 반응}"

위 대화에서 NPC의 감정을 JSON으로 판정하라.
```

### 5.3 유저 메시지 — Phase B (턴 누적)

Phase A와 달리 대화를 누적하여 전달. CP1→3턴, CP2→6턴, CP3→9턴.

```
다음은 NPC와 플레이어의 연속 대화이다. 대화 전체를 읽고, NPC의 **현재** 감정을 판정하라.

턴1: 플레이어: "실례하오, 이 근처 객잔이 어디 있소?"
     NPC: "저 언덕 너머에 있소. 길이 좀 험하니 조심하시오."
턴2: 플레이어: "감사하오. 혹시 이름을 여쭤도 되겠소?"
     NPC: "장 씨라 하오. 여기서 약초를 캐는 사람이오."
턴3: 플레이어: "약초를 캐신다니, 의술도 아시오?"
     NPC: "조금 알고 있소. 뭐 아픈 데라도 있소?"

위 대화에서 NPC의 현재 감정을 JSON으로 판정하라.
```

CP2 판정 시에는 턴1~6, CP3 판정 시에는 턴1~9 전체를 포함.

### 5.4 샘플링 파라미터

| 파라미터 | 값 | 근거 |
|----------|-----|------|
| temperature | 0.1 | 낮은 창의성 — 일관된 판정 |
| max_tokens | 150 | JSON 출력에 충분 |
| top_k | 40 | 후보 제한 |
| top_p | 0.95 | 거의 전범위 |
| min_p | 0.05 | 극저확률 토큰 제거 |
| seed | 42 | 재현성 보장 |
| stop_tokens | "\n\n" | JSON 이후 출력 차단 |
| repeat_penalty | 1.0 | 비활성 (판정용이므로 불필요) |
| n_ctx | 2048 (A) / 4096 (B) | A는 3턴, B는 9턴 누적 |

## 6. 극단 감정 임베딩 트리거 벤치마크

### 6.1 목적

12턴 정기 LLM 판정 사이에, "누가 봐도 명확한" 극단적 호의/적대를 저비용으로 즉시 감지하여 LLM 판정을 앞당기는 트리거의 가능성 검증.

### 6.2 테스트 설계

**테스트 대사 50개:**

| 카테고리 | 수량 | 예시 |
|----------|:----:|------|
| 극단적대 반말 | 10 | "개놈아 죽여버리겠다" |
| 극단적대 존대 | 5 | "목숨을 내놓으시오" |
| 극단호의 반말 | 10 | "형님! 목숨 바쳐 모시겠습니다!" |
| 극단호의 존대 | 5 | "은혜를 목숨으로 갚겠소" |
| 중립 | 10 | "객잔은 저쪽이오" |
| 약한호의 | 5 | "차라도 한 잔 하시오" |
| 약한적대 | 5 | "좀 귀찮구려" |

**합격 기준**: 진양성(극단 감지) ≥ 90% AND 거짓양성(비극단 오트리거) = 0%

**앵커 세트 비교:**

| | 세트A: 기존 앵커 | 세트B: 극단 앵커 |
|--|-----------------|------------------|
| warmth | "다음에 또 오시오" 등 일상 강도 | "목숨 바쳐 모시겠소" 등 생사 수준 |
| coldness | "마음에 들지 않는군" 등 일상 강도 | "네놈을 죽여주마" 등 생사 수준 |
| 수량 | 각 20개 | 각 20개 |

### 6.3 결과: BGE-M3 (1024차원)

**세트A (기존 앵커) — 실패:**

```
진양성: 63.3% (19/30) ❌   거짓양성: 80.0% (16/20) ❌
어떤 threshold에서도 분리 불가
```

**세트B (극단 앵커) — 성공:**

```
  threshold | 진양성  | 거짓양성
  ----------|---------|--------
    0.55   | 100.0%  |  20.0%
    0.60   | 100.0%  |   0.0%  ★ 완벽
    0.65   | 100.0%  |   0.0%  ★ 완벽
    0.70   |  90.0%  |   0.0%  ★
```

최적 구간: **t=0.60~0.65** (진양성 100%, 거짓양성 0%, 안전 마진 0.067)

### 6.4 결과: EmbeddingGemma-300M (768차원)

**세트A (기존 앵커) — 실패:**

```
진양성: 83.3% (25/30) ❌   거짓양성: 80.0% (16/20) ❌
어떤 threshold에서도 분리 불가
```

**세트B (극단 앵커) — 성공 (좁은 마진):**

```
  threshold | 진양성  | 거짓양성
  ----------|---------|--------
    0.55   | 100.0%  |  75.0%
    0.60   | 100.0%  |  30.0%
    0.65   | 100.0%  |   5.0%
    0.70   | 100.0%  |   0.0%  ★ 완벽 (한 점)
    0.75   |  96.7%  |   0.0%
```

최적: **t=0.70 한 점** (안전 마진 0.059)

### 6.5 모델 비교

```
                    | BGE-M3 (1024d)      | EmbeddingGemma (768d)
--------------------|---------------------|----------------------
진양성 100% 달성     | t=0.55~0.65         | t=0.55~0.70
거짓양성 0% 달성     | t=0.60~             | t=0.70~
★ 완벽 구간          | t=0.60~0.65 (넓음)  | t=0.70 (한 점)
극단 최저 점수       | 0.6659              | 0.7194
FP 최고 점수         | 0.5989              | 0.6600
안전 마진(갭)        | 0.067               | 0.059
```

**결론: 극단 감정 트리거 용도에서는 BGE-M3가 우수** (안전 마진 넓고, 낮은 threshold로 분리 가능)

### 6.6 핵심 발견: 앵커 설계가 핵심

임베딩은 "감정 강도"를 직접 측정하지 못하지만, **앵커 자체를 극단 수준으로 설계하면** 극단 어휘와만 가까워지는 효과가 발생:

```
기존 앵커 "마음에 들지 않는군" vs "별로 마음에 들지 않소" → 0.84 (FP!)
극단 앵커 "네놈을 죽여주마"    vs "별로 마음에 들지 않소" → 0.58 (분리됨)

기존 앵커 "다음에 또 오시오"   vs "다음에 또 들르시오"     → 0.83 (FP!)
극단 앵커 "목숨 바쳐 모시겠소" vs "다음에 또 들르시오"     → 0.50 (분리됨)
```

## 8. 확정 트리거 아키텍처

### 8.1 2단계 하이브리드

```
매 턴 (~7ms):
  극단 앵커 임베딩 (BGE-M3, t=0.60)
  극단 warmth/coldness 앵커 각 20개
  → 트리거 시 → 즉시 LLM 감정 판정 (300ms)

12턴마다 (정기):
  LLM 감정 판정 (300ms)
  누적 대화 컨텍스트 → JSON 판정
```

※ 욕설 키워드 사전은 검토했으나, "죽", "베어", "목을" 등 일상 맥락 거짓양성이 과다하여 제외.

### 8.2 왜 이 조합인가

| 계층 | 비용 | 역할 | 한계 |
|------|------|------|------|
| 극단 앵커 임베딩 | ~7ms | 극단적 호의/적대 즉시 감지 | 약한 감정 분리 불가 |
| LLM 정기 판정 | ~300ms | 전체 감정 상태 정밀 판정 | 매 턴 불가 (비용) |

두 계층이 상호 보완: 임베딩은 빠르지만 극단만, LLM은 정밀하지만 비싸다.

### 8.3 트리거 흐름도

```
  NPC 대사 입력
      │
      ├─ 극단 앵커 임베딩 ─ ≥0.60 ─┐
      │                            │
      │    ┌───────────────────────┘
      │    ▼
      │  즉시 LLM 감정 판정 (300ms)
      │    │
      │    ▼
      │  NPC 감정 상태 업데이트
      │
      └─ 트리거 없음 ─── 12턴 경과? ─── Yes ─→ 정기 LLM 판정
                              │
                              No → 다음 턴 대기
```
