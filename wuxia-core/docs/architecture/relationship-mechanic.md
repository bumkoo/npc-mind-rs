## 1. 2축 관계 모델

### 1.1 축 정의

| 축 | 범위 | 핵심 질문 | 특성 |
|---|---|---|---|
| 호감도(affinity) | -100 ~ +100 | "이 사람이 좋은가 / 싫은가?" | 양수=호감, 음수=적대 |
| 신뢰도(trust) | 0 ~ 100 | "등을 맡길 수 있는가?" | 상승 느림, 하락 빠름 |

```
  호감도 스펙트럼:
  -100 ──────── -40 ──── 0 ──── +40 ──────── +100
  원수          적대    무관심    호감          깊은 애정

  신뢰도 스펙트럼:
  0 ────── 20 ────── 50 ────── 70 ────── 100
  경계       의심      보통      신뢰      절대 신뢰
```

### 1.2 3축→2축 변경 배경

기존 3축(호감도/적대도/신뢰도)에서 2축으로 변경한 이유:

- 호감도와 적대도를 분리하면 "호감 높고 적대도 높은 인물"이 발생 → 행동 결정 모호
- NPC AI(Gemma 4B)가 3축을 동시에 고려하는 것은 비현실적
- 호감도를 -100~+100으로 확장하면 적대를 음수로 자연스럽게 표현 가능
- 복잡도 대비 서사적 효과가 낮음

### 1.3 무협 검증

| 관계 | 호감도 | 신뢰도 | 해석 |
|---|---|---|---|
| 소연↔주인공 (초기) | +30 | 20 | 호기심 있지만 경계 |
| 소연↔사부 | +80 | 90 | 깊은 유대 |
| 소연↔조고 | -90 | 0 | 원수 |
| 설화↔바투 | -30 | 20 | 싫지만 완전 무지는 아님 |
| 령호충↔전보광 | +10 | 10 | 적이었다가 약간 인정 |
| 장무기↔조민 | +60 | 30 | 좋아하지만 완전히 못 믿음 |

## 2. RelationshipLevel 판정

### 2.1 판정 기준 (8단계)

```
  적대 영역 (우선 판정):
    호감 <= -80                    → Enemy (원수)
    호감 <= -40                    → Hostile (적대)
    호감 <= -10                    → Wary (경계)

  중립~우호 영역:
    호감 <  20                     → Stranger (모르는 사이)
    호감 >= 20                     → Acquaintance (아는 사이)
    호감 >= 50 AND 신뢰 >= 30     → Friendly (친근)
    호감 >= 70 AND 신뢰 >= 50     → Close (가까운 사이)
    호감 >= 80 AND 신뢰 >= 70     → Intimate (깊은 유대)
```

### 2.2 판정 흐름

```
  is_affinity <= -80? ──yes──▶ Enemy
       │no
  is_affinity <= -40? ──yes──▶ Hostile
       │no
  is_affinity <= -10? ──yes──▶ Wary
       │no
  is_affinity < 20?   ──yes──▶ Stranger
       │no
  is_affinity >= 80
  AND trust >= 70?    ──yes──▶ Intimate
       │no
  is_affinity >= 70
  AND trust >= 50?    ──yes──▶ Close
       │no
  is_affinity >= 50
  AND trust >= 30?    ──yes──▶ Friendly
       │no
  else ────────────────────▶ Acquaintance
```

### 2.3 특수 관계 유형

RelationshipLevel과 별도로 관계 유형(RelationType)이 존재한다:

| 유형 | 조건 | 효과 |
|---|---|---|
| 사제(Master-Disciple) | 이벤트 기반 | 기연 조건②, 성장 보너스 |
| 연인(Lover) | 호감 80+, 신뢰 70+, 특정 이벤트 | 피로 회복 -20/일 |
| 의형제(SwornSibling) | 호감 70+, 신뢰 60+, 의식 이벤트 | 시간 감쇠 최저 한계 상향 |
| 주종(Lord-Servant) | 이벤트 기반 | 충(忠) 관련 판정 |

## 4. 대화(Conversation) 이벤트 — 호감도 변경 메카니즘

### 4.1 설계 원칙

- 대화에서는 **호감도만** 변경한다
- 신뢰는 "행동"으로 쌓이는 것이지 "말"로 쌓이는 것이 아니다
- LLM 태그([affinity: N]) 방식은 **폐기** — Gemma 4B/12B 모두 태그 품질이 신뢰 불가
- 대체 방식: **임베딩 감정 분석(매 턴) + LLM 판정(특정 시점)**

### 4.2 전체 흐름

```
  매 턴 (소폭 변화, ~28ms):
  ═══════════════════════════
  NPC 대사 생성 (LLM)
       │
       ▼
  대사를 임베딩 (embeddinggemma, ~28ms)
       │
       ▼
  감정 앵커와 cosine similarity 비교
       │
       ▼
  warmth/coldness 유사도 → 호감도 ±1~3
       │
       ▼
  감정 누적 버퍼에 기록


  특정 시점 (중폭 보정):
  ═══════════════════════════
  트리거: 감정 누적 임계치 도달 OR 대화 종료(end())
       │
       ▼
  최근 대화 요약을 LLM에 전달
  "이 대화에서 NPC의 호감이 어떻게 변했나?" 판정
       │
       ▼
  호감도 ±1~10 보정
```

### 4.3 임베딩 감정 앵커

NPC 대사를 임베딩하고, 미리 정의한 감정 앵커 문장과 유사도를 비교한다.

**대화 이벤트는 호감도만 변경하므로 warmth/coldness 2카테고리만 필요:**

```
  warmth (호감↑):
    "정말 고마운 일이오"
    "그대와 함께여서 기쁘오"
    "마음이 따뜻해지는구려"
    "그대의 마음을 알겠소"
    "참으로 반가운 벗이로다"

  coldness (호감↓):
    "더 이상 할 말이 없소"
    "그대와는 인연이 아닌 듯하오"
    "귀찮게 하지 마시오"
    "꺼져라, 볼 꼴이 못 된다"
    "네놈 따위와는 상종 않겠다"
```

**유사도 → 호감도 변화량 매핑:**

```
  cosine_similarity    변화량(delta)
  ──────────────────────────────────
  < 0.55              0 (무반응)
  0.55 ~ 0.65         ±1
  0.65 ~ 0.75         ±2
  0.75+               ±3

  매 턴 clamp: ±3 (임베딩만으로 급격한 변화 방지)
```

**판정 로직:**

```
  warmth_sim = max(cosine_sim(대사, warmth_anchor) for each anchor)
  coldness_sim = max(cosine_sim(대사, coldness_anchor) for each anchor)

  if warmth_sim > coldness_sim AND warmth_sim >= 0.55:
      delta = +map_to_delta(warmth_sim)
  elif coldness_sim > warmth_sim AND coldness_sim >= 0.55:
      delta = -map_to_delta(coldness_sim)
  else:
      delta = 0  (중립 대사)
```

### 4.4 LLM 판정 (특정 시점)

**트리거 조건 (B+D):**

- **B: 감정 누적 임계치** — 임베딩 delta 절대값 합계가 임계치 도달
- **D: 대화 종료** — end() 호출 시

```
  감정 누적 버퍼:
    turn 1: delta +1
    turn 2: delta +2
    turn 3: delta -1
    turn 4: delta +3
    → 절대값 합계 = |1| + |2| + |1| + |3| = 7

  임계치 예시: 8 (조정 필요)
    7 < 8 → 아직 트리거 안 됨
    turn 5: delta +2 → 합계 9 >= 8 → LLM 판정 트리거!
```

**LLM 판정 시 질문:**

```
  [대화 요약]
  ...최근 N턴 대화 내용 요약...

  [질문]
  이 대화에서 {npc_name}의 {player_name}에 대한 호감이 어떻게 변했는가?
  -10(매우 나빠짐) ~ +10(매우 좋아짐) 범위에서 숫자 하나만 답하라.
```

**LLM 판정 변화량:**

```
  매 턴 임베딩 delta clamp:  ±3
  LLM 판정 delta clamp:     ±10
  대화 1회(세션) 총 변화량:  미정 (설계 후 밸런스 테스트 필요)
```

### 4.5 기존 [affinity: N] 태그 폐기 사유

| 문제 | 상세 |
|---|---|
| 태그 누락 | Gemma 4B에서 빈번히 발생, 12B에서도 간헐 발생 |
| 값 이상 | [affinity: +47] 등 범위 초과 값 출력 |
| 방향 오류 | 적대 대사인데 양수 태그 부착 |
| 형식 오류 | [affinity +3], [afinity: 3] 등 파싱 실패 |
| 근본 원인 | 소형 LLM은 "대사 생성"과 "수치 판단"을 동시에 잘 못함 |

→ LLM은 대사 생성에만 집중, 수치 판단은 임베딩+코드가 담당

### 4.6 대화가 도메인이 아닌 이유

```
  대화 = Application Layer (ChatSession)
    │
    ├─ LLM Adapter 호출 → 대사 생성
    ├─ 기억 도메인 → 관련 기억 검색/저장
    ├─ 관계 도메인 → 호감도 변경 (이 문서의 범위)
    ├─ 심리 도메인 → (향후) 감정 변화
    └─ 서사 도메인 → (향후) 스토리 이벤트 트리거
```

## 5. 시간(Time) 이벤트 — 감쇠 규칙

### 5.1 미접촉 감쇠

```
  미접촉 기간        호감도 감쇠     신뢰도 감쇠
  ──────────────────────────────────────────
  3개월 미접촉       -1/월           0
  6개월 미접촉       -2/월           -1/월
  12개월 이상        -3/월           -2/월
```

### 5.2 최저 한계 (감쇠 바닥)

| 관계 유형 | 호감도 최저 | 신뢰도 최저 |
|---|---|---|
| 일반 관계 | 원래 값의 30% | 원래 값의 20% |
| 의형제/사제 | 원래 값의 50% | 원래 값의 40% |

### 5.3 적대 감쇠 특수 규칙

- 호감도가 음수(적대)인 경우에도 시간이 지나면 0 방향으로 감쇠
- 단, 심리 도메인의 복수(復) 가치가 0.7 이상이면 적대 감쇠 완전 차단

## 6. 나머지 이벤트 소스 — 변화 패턴 요약

| 상황 | 호감도 | 신뢰도 |
|---|---|---|
| 함께 싸움(공동) | +5~+10 | +10~+20 |
| 서로 싸움(적대) | -10~-20 | -5~-10 |
| 비무(우호) | +3~+5 | +5~+8 |

### 6.2 구출/보호(Rescue) — 향후 구현

| 상황 | 호감도 | 신뢰도 |
|---|---|---|
| 위기에서 구함 | +10~+20 | +15~+25 |

→ 무협에서 가장 강력한 관계 전환 이벤트

### 6.3 배반/속임수(Betrayal) — 향후 구현

| 상황 | 호감도 | 신뢰도 |
|---|---|---|
| 약속 파기 | -10~-15 | -20~-30 |
| 비밀 누설 | -15~-25 | -25~-40 |
| 함정 | -30~-50 | -40~-60 |

### 6.4 선물/호의(Gift) — 향후 구현

| 상황 | 호감도 | 신뢰도 |
|---|---|---|
| 약초/영약 | +5~+15 | +2~+5 |
| 무기/비급 | +10~+20 | +5~+10 |

### 6.5 함께수련(Training) — 향후 구현

| 상황 | 호감도 | 신뢰도 |
|---|---|---|
| 동료와 단련 | +3~+5 | +5~+10 |
| 스승 가르침 | +5~+10 | +10~+15 |

### 6.6 간호/돌봄(Care) — 향후 구현

| 상황 | 호감도 | 신뢰도 |
|---|---|---|
| 부상 간호 | +10~+20 | +5~+10 |
| 독 치료 | +15~+25 | +10~+15 |

### 6.7 조직/세력(Faction) — 향후 구현

- 같은 문파 가입: 기본 호감 보너스
- 적대 세력 발각: 호감↓
- 정사대전: 진영별 일괄 변화

### 6.8 경제/거래(Trade) — 향후 구현

- 공정 거래 반복: 신뢰 +1~+3 (느림)
- 사기/속임: 신뢰 -10~-20

### 6.9 공간/동행(Proximity) — 향후 구현

- 장기간 동행: 호감↑ (천천히)
- 위험 지역 함께 통과: 신뢰↑

## 7. 심리 보정 (향후)

현재 MVP에서는 성격/가치관에 의한 보정 없음. 향후 도입 계획:

### 7.1 3계층 구조

```
  Layer 1: 이벤트 기본값 (이 문서 §4~§6의 수치)
  Layer 2: 심리 보정 (성격 계수 × 가치관 계수)
  Layer 3: 비대칭 + 감쇠

  최종Δ = 기본Δ × 성격계수 × 가치관계수 × 비대칭계수
```

### 7.2 성격(HEXACO) 보정 예시

- A(친화성) 높음: 긍정 상호작용 호감 ×1.3
- A(친화성) 낮음: 모욕에 호감 하락 ×1.5
- E(정서성) 높음: 구출 시 호감 ×1.3
- X(외향성) 높음: 대화 호감 ×1.2

### 7.3 5가치 보정 예시

- 의(義) 높음: 구출 신뢰 ×1.5, 배반 시 호감 하락 ×2.0
- 충(忠) 높음: 같은 조직 기본 호감 +5
- 복수(復) 높음: 적대(호감 음수) 감쇠 속도 ×0.5
