## 2. 도메인별 상세 분석

### 2.1 캐릭터 도메인 (Character) — [v1.0 피로/부상 추가]

> "이 존재는 누구인가?"  
> 비유: 호적부 + 건강기록부 — 신원과 현재 신체 상태

**소유 데이터**:
- CharacterId (고유 식별자)
- 이름, 자(字)
- 성별
- 나이
- 역할 (Player / Npc / Companion)
- **피로 (fatigue: u32, 0~100)** [v1.0 추가]
- **부상 (injury: Option\<Injury\>)** [v1.0 추가]

**역할(CharacterRole) 상세**:
- **Player**: 플레이어가 직접 조종
- **Npc**: LLM으로 구동되는 사람 캐릭터
- **Companion**: 동물/영수 (신조, 한혈보마 등)

**Companion이 캐릭터인 이유**:
- 감정이 있음 (심리 도메인 연결, 단순화된 버전)
- 성장함 (성장 도메인 연결)
- 관계가 있음 (주인과의 유대)
- 죽음 (수명이 있음)

**다른 도메인과의 관계**:
- 모든 도메인이 CharacterId를 참조하여 자기 데이터를 관리
- 캐릭터 도메인 자체는 다른 도메인의 데이터를 소유하지 않음

**경계 결정 기록**:
- 문파 소속 → 세계관 도메인 소유 (캐릭터가 아님)
- 감정/성격/가치관 → 심리 도메인 소유
- 능력치/무공 → 성장 도메인 소유
- 인간관계 → 관계 도메인 소유
- **피로/부상 → 캐릭터 도메인 소유** [v1.0 결정]

**피로가 캐릭터 도메인에 있는 이유** [v1.0 신설]:
```
피로는 수련에서만 쌓이는 게 아니다:
  - 단련/연마 → 피로↑ (성장 도메인 활동)
  - 전투 → 피로↑ (전투 도메인 활동)
  - 여행/이동 → 피로↑ (공간 도메인 활동)
  - 탐험 → 피로↑ (서사/공간 도메인 활동)

모든 활동에서 쌓이므로 → 특정 도메인이 아닌 캐릭터의 속성
```

#### 피로 시스템 [v1.0 신설]

**피로 단계**:

| 범위 | 상태 | 설명 |
|------|------|------|
| 0~20 | 양호 | "몸이 가볍다" |
| 21~40 | 경미 | "좀 피곤하다" |
| 41~60 | 보통 | "쉬고 싶다" |
| 61~80 | 심각 | "몸이 무겁다, 집중이 안 된다" |
| 81~100 | 탈진 | "더 이상 움직일 수 없다" |

**피로가 쌓이는 곳**:

| 활동 | 피로 누적 | 감소 요인 |
|------|----------|----------|
| 능력치 단련 | 강도 × 3~5 | 인내 높으면 경감 |
| 무공 연마 | 강도 × 2~4 | 단련보다 약간 덜 |
| 전투 | 상대 강도 비례 | 체력 높으면 경감 |
| 여행/이동 | 거리 비례 | 경공 높으면 경감 |
| 탐험(위험지역) | 고정 + 랜덤 | — |
| 야간 활동 | +10 추가 | — |

**능력치에 의한 피로 경감 공식**:
```
여행 피로 = 기본 피로 × (100 - 경공) / 100
전투 피로 = 기본 피로 × (100 - 체력) / 100
단련 피로 = 기본 피로 × (100 - 인내) / 100
```

**피로 회복 — 기본**:

| 활동 | 피로 회복 |
|------|----------|
| 하루 휴식 (아무것도 안 함) | -10/일 |
| 수면 (매일 자동) | -5/밤 |

**피로 회복 — 장소 (공간 도메인 연동)**:

| 장소 | 피로 회복 | 무협적 장면 |
|------|----------|-----------|
| 온천 | -20/일 | "따뜻한 물에 피로가 녹는다" |
| 약초밭 근처 | -15/일 | "약초 향이 기운을 돋운다" |
| 사찰/도관 | -15/일 | "고요한 곳에서 마음이 편해졌다" |
| 자기 문파 | -12/일 | "익숙한 곳이라 편하다" |
| 객잔(여관) | -10/일 | "밥 먹고 잠자고" |
| 야외 노숙 | -3/일 | "딱딱한 바닥에 잠이 안 온다" |

**피로 회복 — 사람 (관계 도메인 연동)**:

| 관계 | 피로 회복 | 조건 | 무협적 장면 |
|------|----------|------|-----------|
| 연인/애인 | -20/일 | 호감도 80+, 신뢰도 70+ | "그녀와 함께 있으니 근심이 사라진다" |
| 절친한 벗 | -15/일 | 호감도 70+ | "오랜 벗과 술 한잔에 피로가 풀린다" |
| 사제(스승) | -10/일 | 신뢰도 60+ | "스승님 곁이 편안하다" |
| 동료 | -8/일 | 호감도 50+ | "동료들과 있으니 마음이 놓인다" |
| **적대 관계** | **+5/일** | 호감도 -40 이하 | "저놈이 근처에 있어 긴장이 안 풀린다" |

**피로 회복 — 아이템 (사물 도메인 연동)**:

| 아이템 | 피로 회복 | 추가 효과 |
|--------|----------|----------|
| 일반 영약 | -15 (즉시) | — |
| 상급 영약 (천산설련 등) | -30 (즉시) | — |
| 독주(烈酒) | -10 (즉시) | 의지 일시+5, 다음날 피로+5 (숙취) |
| 보양식 | -10/일 | 3일간 지속 |
| 해독약 | -20 (즉시) | 부상(중독) 해제 |

**피로 회복 중첩** — 장소 + 사람 + 아이템 조합 가능:
```
최악: 야외 노숙(-3) + 적대자 근처(+5) = +2/일 (피로가 오히려 쌓임)
보통: 객잔(-10) + 수면(-5) = -15/일
최상: 온천(-20) + 연인(-20) + 상급 영약(-30) = -70 즉시
```

#### 부상 시스템 [v1.0 신설]

**부상 발생 조건 — 피로 기반**:

| 피로 수준 | 활동 시 부상 확률 |
|----------|-----------------|
| 0~79 | 0% (강도에 의한 부상만) |
| 80~90 | 10% |
| 91~100 | 25% |
| 100 (탈진) | 강제 휴식, 아무것도 못 함 |

**부상 발생 조건 — 수련 강도 기반**:

| 단련/연마 강도 | 부상 확률 | 부상 결과 |
|--------------|----------|----------|
| 1~4 | 0% | 안전 |
| 5~6 | 5% | 경상: 3일 수련 불가 |
| 7~8 | 15% | 중상: 7일 수련 불가, 체력 일시 -5 |
| 9~10 | 30% | 중상: 14일 수련 불가, 체력 일시 -10 |

의지 보너스로 한계를 넘긴 강도분은 부상 확률 +10% 추가.

**부상 회복**:

| 방법 | 회복 기간 | 추가 효과 |
|------|----------|----------|
| 혼자 회복 | 7일 | — |
| 의원 NPC | 3일 | 돈 필요 |
| 동료 간호 | 5일 | 호감도/신뢰도 상승 |
| 연인 간호 | 4일 | 호감도 대폭 상승 |

**부상이 게임에서 만드는 서사**:
```
부상 발생!
  │
  ├─ 수련 불가 → 이 시간에 뭘 하지?
  │   ├─ 탐험하러 간다      → 새 장소 발견
  │   ├─ 사람을 만난다      → 관계 발전
  │   └─ 비급을 읽는다      → 지혜 관련 활동
  │
  └─ 치료가 필요하다
      ├─ 혼자 회복 (느림)
      ├─ 의원 NPC (빠름, 돈 필요)
      └─ 동료/연인 간호 (관계 발전 계기)
```

**[v1.0 구현 완료]**: Character struct, LifeStage, CharacterEvent enum 구현됨.  
**[v1.0 미구현]**: fatigue, injury 필드 추가 예정.

### 2.2 심리 도메인 (Psychology) — [v1.5 7층 아키텍처 반영]

> "이 사람은 어떤 마음을 가졌나?"  
> 비유: 인물의 내면 독백 — 소설에서 캐릭터의 생각과 감정  
> 📎 7층 아키텍처 전체 상세: [npc-psychology-architecture.md](../psychology/npc-psychology-architecture.md)  
> 📎 OCC 감정 22종 상세: [occ-emotion-detail.md](../psychology/occ-emotion-detail.md)  

#### 能/性/敍/判 프레임워크 [v1.5 확장]

심리 도메인과 성장 도메인의 경계를 명확히 하기 위해 **네 가지 질문**으로 분류한다:

```
  질문                      답의 종류     소유 도메인       예시
  ──────────────────────────────────────────────────────────────
  "할 수 있는가?"           능력(能)      성장 도메인        의지, 공감, 내공
  "원래 그런 사람인가?"     성향(性)      심리/성격 (①층)    H(정직-겸손), X(외향성)
  "어떤 존재인가?"          서사(敍)      심리/3축 (②층)     믿음, 옳음, 바람
  "상황에서 어떻게          판단(判)      심리/5가치 (③층)    충, 의, 효, 복수, 야망
   판단하는가?"
```

**핵심 구분 원칙**: 
- 같은 감정 관련 단어라도 **"할 수 있는가"**이면 성장 도메인, **"원래 그런가"**이면 심리 도메인이다.
- 예: 공감(empathy) 능력 = 80 → "타인 감정을 잘 읽을 수 있다" (성장 도메인)
- 예: A(친화성) = 0.9 → "원래 도발에도 참고 용서하는 성격이다" (심리 도메인)
- 츤데레 = 공감(능력) 높음 + A(친화성, 성향) 낮음 → 두 도메인이 독립적으로 작동하는 증거
- H(정직-겸손) 추가로 "본질적으로 남을 이용하는 사람인가?"를 ①층에서 직접 표현 가능 [v2.0]
- **敍와 判의 분리**: 같은 옳음 0.9라도 명경("도의를 지킨다")과 조고("힘이 정의다")는 정반대 인물이다. 수치(判)만으로는 구분 불가, 신조 텍스트(敍)가 결정적 차이를 만든다.

#### 7층 아키텍처 요약

NPC의 내면은 7개 층으로 구성된다. 위로 갈수록 안정적이고, 아래로 갈수록 빠르게 변한다:

```
  거의 변하지 않는 층:
  ① 성격 (HEXACO)          — 행동 패턴의 기질적 토대
  
  천천히 변하는 층:
  ② 3축 가치관 (믿음/옳음/바람) — "이 사람이 어떤 존재인가" (LLM용 서사)
  ③ 5가치 (충/의/효/복수/야망) — "어떻게 판단하는가" (OCC용 수식)
  
  빠르게 변하는 층:
  ④ 감정 (OCC 22종 인지평가)  — "지금 무엇을 느끼는가"
  ⑤ 기분 (PAD 3차원)         — "전반적으로 어떤 상태인가"
  ⑥ 행동 (Utility AI → LLM)  — "무엇을 하는가"
  
  메타 층:
  ⑦ 성찰 (Tier 1~4)          — ①~⑥ 모든 층을 재평가
```

> 📎 각 층의 상세 정의, 수치, 공식: [npc-psychology-architecture.md](../psychology/npc-psychology-architecture.md) §2~§9

#### 세 개의 Aggregate [v1.5 변경: 2개→3개]

심리 도메인은 **세 개의 독립 Aggregate**를 가진다.

```
psychology/
├── personality.rs    ← Aggregate 1: HexacoPersonality (①층, 性) [v2.0]
├── three_axis.rs     ← Aggregate 2: ThreeAxisValues (②층, 敍) ← [v1.5 신규]
├── values.rs         ← Aggregate 3: WuxiaValues (③층, 判)    ← [v1.5 역할 재정의]
├── emotion.rs        ← OccEmotion + PADState (④⑤층)
├── behavior.rs       ← UtilityAI 행동 범주 (⑥층)
├── reflection.rs     ← 성찰 Tier 1~4 (⑦층)
└── memory.rs         ← MemoryStream (LanceDB 연동)
```

**분리 근거**:
- 성격(①)과 가치관(②③)은 **독립적으로 변한다** (배신 → 가치관만 변함, 은둔 → 성격만 변함)
- 3축(②)과 5가치(③)는 **사용처와 변화 속도가 다르다** (3축=LLM 서사, 5가치=OCC 수식)
- Aggregate는 "같이 변하는 것"을 묶는 단위 → 따로 변하면 분리

**Aggregate 1 — 성격 (HexacoPersonality, ①층)** [v2.0 BigFive→HEXACO 변경]:
- H(정직-겸손) / E(정서성) / X(외향성) / A(친화성) / C(성실성) / O(개방성) (각 f32, 0.0~1.0)
- 특징: 거의 변하지 않음. Tier 4(인생 성찰)에서만 ±0.05 제한, 최대 2요인.
- 나이 drift 없음 (6요인 전부). 성격은 경험(Tier 4 성찰)으로만 변한다.
- 하위 층에 필터 역할: H→죄책감/통쾌 필터, E→두려움/공감, A→분노/원한, X→표현 강도 등
- 📎 HEXACO 상세, BigFive 차이점, 6인 NPC 프로필: [npc-psychology-architecture.md](../psychology/npc-psychology-architecture.md) §2

**Aggregate 2 — 3축 가치관 (ThreeAxisValues, ②층)** [v1.5 신규]:
- 믿음(信) / 옳음(正) / 바람(願) (각 축 = 강도 f32 + 신조 String + 형성기억 + 대안후보[])
- 특징: 천천히 변함. 강도는 Tier 1~2에서 ±0.05~0.1, 신조는 Tier 3~4에서만 전환 가능.
- **LLM 프롬프트 전용** — OCC 수식에 직접 투입되지 않음.
- 같은 수치라도 신조(방향)가 다르면 완전히 다른 인물 (명경 옳음 0.9 "도의" ≠ 조고 옳음 0.9 "힘")

**Aggregate 3 — 5가치 (WuxiaValues, ③층)** [v1.5 역할 재정의]:
- 충(忠) / 의(義) / 효(孝) / 복수(復) / 야망(野) (각 f32, 0.0~1.0)
- 특징: 중간 속도로 변함. Tier 1~3에서 ±0.05~0.2.
- **OCC 감정 평가 수식의 직접 입력** — 코드가 <1ms에 계산.
- 예: 의(0.9) × 위반강도(0.9) = 분노(0.81)

#### 3축 ↔ 5가치: 성찰을 통한 양방향 해석 관계

3축과 5가치는 자동계산도, 완전 독립도 아닌 **해석 관계**다. 성찰(⑦층)이 양자를 번역하는 역할을 한다:

```
  ②층 3축 (믿음/옳음/바람 + 신조)
     │                              ▲
     │  ⬇ 하향 압력                  │  ⬆ 상향 신호
     │  3축이 크게 변하면             │  5가치의 누적 변화가
     │  → 다음 성찰에서               │  쌓이면 Tier 3~4 성찰에서
     │    5가치에 압력 반영            │  3축 신조에 균열 발생
     ▼                              │
  ③층 5가치 (충/의/효/복수/야망)     │
     │                              │
     │ 수식 입력 (코드, <1ms)         │
     ▼                              │
  ④층 OCC → ⑤층 PAD → 감정 누적 ───┘
                           │
                    ⑦층 성찰 (LLM)
                    코드: 범위 제한 (clamp)
                    LLM: 내용 결정 (어떤 가치가 어떻게 변하는지)
```

**불일치는 자연스럽다** — 이것이 인물의 깊이를 만든다:
- 진야림: 옳음 0.4(부서진 상태)인데 의 0.6 → 원칙은 무너졌지만 몸에 밴 의리는 남아있다 (관성)
- 소연: 믿음 0.5인데 충 0.7 → 사부 한 사람에게 집중된 믿음(信)이 높은 충성으로 발현

> 📎 해석 관계 상세, 6인 NPC 검증 데이터: [npc-psychology-architecture.md](../psychology/npc-psychology-architecture.md) §5, §12

#### 코드/LLM 역할 분담

```
  🔧 코드 (확정적, <1ms, 매번 같음):
     OCC 감정 계산, PAD 갱신, Utility AI 행동 범주, 성찰 트리거 판단, 변화 범위 clamp

  🧠 LLM (창의적, 가끔 호출):
     구체적 대사/행동, 하루 계획, 기억 중요도 재평가, 신조 뉘앙스 변화/전환 판단

  🔧+🧠 협업 (코드가 범위 제한, LLM이 내용 결정):
     3축 강도 조정, 5가치 조정, 성격 변화, 신조 전환
```

> 📎 코드/LLM 역할 분담 상세: [npc-psychology-architecture.md](../psychology/npc-psychology-architecture.md) §11

#### 감정 시스템 (OCC + PAD, ④⑤층) — [v1.5 설계 완료]

- OCC 22종 인지 평가: 사건/행동/대상을 5가치 기준으로 평가하여 감정 생성

#### 심리 도메인과 성장 도메인의 연결 (수련 효율) [v1.5 OCC 용어 갱신]

심리 도메인의 감정과 성격은 성장 도메인의 수련 효율에 영향을 준다:

```
OCC 감정 → 수련 효율 계수:
  Joy(희열)      → 전반적 ×1.1
  Anger(분노)    → 무력 ×1.5, 내공 ×0.7
  Distress(고뇌) → 공감 ×1.4, 무력 ×0.6
  Fear(두려움)   → 경공 ×1.3, 의지 ×0.5

OCC 감정 → 무공 적합도 (기연 조건④):
  독고구검 ↔ Joy/Relief    (마음이 편해야 깨달음)
  항룡십팔장 ↔ Pride        (강한 자부심이 필요)
  구음백골조 ↔ Anger/Hate   (어두운 감정이 맞음)
```

#### 기억 스트림 → 기억(Memory) 도메인으로 독립 [v2.1]

- 기억 데이터와 검색 로직은 독립된 기억 도메인(§2.13)이 소유한다.
- 심리 도메인은 성찰(⑦층) 시 기억 도메인의 Port를 통해 기억을 저장/검색한다.
- 📎 상세: [memory-domain-analysis.md](memory-domain-analysis.md)

#### LLM과의 관계

- 심리 도메인은 데이터와 규칙의 주인
- LLM Adapter는 성찰/대사 생성 시 호출되는 도구 (인프라)
- 심리 도메인이 "성찰이 필요하다"고 판단 → LLM Adapter에 요청 → 결과를 기억에 저장
- 프롬프트에는 3축+신조가 포함되고, OCC/PAD 상태가 컨텍스트로 제공됨

### 2.3 성장 도메인 (Growth) — [v1.0 대폭 보강]

> "이 사람은 얼마나 강한가, 어떻게 변하나?"  
> 비유: 수련일지 — 단련과 연마의 기록, 무공의 경지

**소유 데이터**:
- 능력치 (9개, 모두 **"할 수 있는가"** 에 해당하는 능력)
  - 지적(Intellectual): 내공, 지혜, 책략
  - 육체(Physical): 체력, 경공, 무력
  - 감정(Emotional): 의지, 인내, 공감 ← **능력이지 성향이 아님**
- **무공 프로필 (습득한 무공 목록, 숙련도, 경지)** [v1.0 확장]
- **단련/연마 기록** [v1.0 용어 확정]

#### 용어 정의 [v1.0 신설]

| 용어 | 영문 | 코드명 | 대상 | 설명 |
|------|------|--------|------|------|
| 단련(鍛鍊) | Conditioning | `train_stat()` | StatType 9개 | 기본 능력치를 올리는 행위 |
| 연마(練磨) | Practice | `train_art()` | MartialArt | 무공 숙련도를 올리는 행위 |

```
단련 = 토양을 기름지게 하는 것
  "산을 뛰어다니며 경공을 단련했다"
  → 경공(Agility) 능력치 +N

연마 = 토양 위에 나무를 심고 키우는 것
  "독고구검 제3초를 밤새 연마했다"
  → 독고구검 숙련도 +N, 관련 능력치 소폭 +1~2 (부산물)
```

**단련/연마 선택 구조**:
```
오늘 뭘 하지?
  │
  ├─ ① 단련 (train_stat)
  │   → 능력치 집중 성장
  │   → 무공 숙련도는 안 오름
  │
  ├─ ② 연마 (train_art)
  │   → 숙련도 성장 + 능력치 소폭 (부산물)
  │   → 두 마리 토끼, 각각 느림
  │
  └─ ③ 기타 (탐험, 관계, 휴식)
      → 수련 안 되지만 다른 것을 얻음
```

#### 부산물 효과 (연마 → 능력치) [v1.0 신설]

연마 시 해당 무공의 주 관련 능력치가 소폭 상승 (본업 대비 약 20~30%):

| 무공 유형 | 주 관련 능력치 | 부산물 예시 |
|-----------|--------------|-----------|
| 외공/권법 (항룡십팔장) | 무력, 체력 | 무력 +1 |
| 경공류 (능파미보) | 경공, 체력 | 경공 +1 |
| 내공 심법 (구양신공) | 내공, 의지 | 내공 +1 |
| 병기술 (독고구검) | 무력, 경공 | 무력 +1 |
| 암기류 (만천화우) | 책략, 경공 | 책략 +1 |

#### 능력치 체계 (구현 완료 ✅)

**9개 능력치 (StatType)**:

| 범주 | 능력치 | 영문 | 설명 | 범위 |
|------|--------|------|------|------|
| 지적(Intellectual) | 내공 | InnerPower | 기를 다루는 능력 | 0~100 |
| | 지혜 | Wisdom | 통찰력, 사리판단 | 0~100 |
| | 책략 | Strategy | 전략적 사고 | 0~100 |
| 육체(Physical) | 체력 | Vitality | 건강, 지구력 | 0~100 |
| | 경공 | Agility | 몸놀림, 빠르기 | 0~100 |
| | 무력 | Strength | 물리적 전투력 | 0~100 |
| 감정(Emotional) | 의지 | Willpower | 거부/저항하는 힘 | 0~100 |
| | 인내 | Endurance | 고된 수련을 견딤 | 0~100 |
| | 공감 | Empathy | 타인 감정을 읽는 능력 | 0~100 |

**감정 범주가 성장 도메인에 있는 이유**:
```
  의지(willpower) → "거절을 버틸 수 있는 정신력이 있는가?"  → 능력
  인내(endurance)  → "고된 수련을 견딜 수 있는가?"           → 능력
  공감(empathy)    → "상대의 감정을 읽을 수 있는가?"         → 능력

  vs. 심리 도메인:
  친화성 → "원래 거절을 잘 못하는 성격인가?"  → 성향
  의리   → "의리상 들어줘야 한다고 믿는가?"    → 신념
```
수련으로 올리고 노화로 떨어지는 것은 **능력**이므로 성장 도메인이 소유한다.

**능력치 범위**: 0~100 (clamp), 천재기연 시 상한 돌파 가능 (100→105)
```
  0  = 일반인 이하 (부상, 극도의 쇠퇴)
  10 = 일반인 평균 (new_default 기본값)
  30 = 무림 입문
  50 = 중급 무인
  70 = 일류 고수
  90 = 절정 고수
  100 = 전설급 (장삼봉, 독고구패)
```

#### 단련 메카닉

**기본 성장 공식** (구현 완료 ✅):
```
성장량 = intensity × growth_multiplier(life_stage)
최소 1 보장 (수련했으면 아무리 늙어도 1은 오름)
```

| 생애 단계 | 나이 | 계수 |
|-----------|------|------|
| 청년(Youth) | ~32세 | ×1.5 |
| 장년(Prime) | 33~54세 | ×1.0 |
| 중년(Middle) | 55~68세 | ×0.7 |
| 노년(Elder) | 69세~ | ×0.3 |

**연간 자동 노화** (구현 완료 ✅):

매년 수련과 무관하게 자동 적용:

|  | 체력 | 경공 | 무력 | 내공 | 지혜 | 책략 | 의지 | 인내 | 공감 |
|--|------|------|------|------|------|------|------|------|------|
| 청년(~32) | +1 | +1 | +1 | 0 | 0 | 0 | 0 | 0 | 0 |
| 장년(33~54) | 0 | 0 | 0 | +1 | +1 | +1 | 0 | 0 | 0 |
| 중년(55~68) | -1 | -1 | 0 | +1 | +2 | +1 | +1 | 0 | +1 |
| 노년(69~) | -2 | -2 | -1 | 0 | +1 | +1 | 0 | -1 | 0 |

**최대 강도 메카닉** [v1.0 신설, 미구현 ❌]:

플레이어가 원하는 만큼 수련할 수 없다. 능력치와 상태가 상한선을 결정한다:

```
기본 최대 강도 = (체력 + 인내) / 20
의지 보너스   = 의지 70 이상이면 +1
현재 피로 감산

최종 최대 강도 = 기본 + 의지보너스 - 현재피로  (최소 1, 최대 10)
```

예시:

| 상태 | 체력 | 인내 | 의지 | 피로 | 최대 강도 |
|------|------|------|------|------|----------|
| 건강한 청년 | 60 | 40 | 50 | 0 | 5 |
| 지친 청년 | 60 | 40 | 50 | 2 | 3 |
| 의지 강한 노인 | 25 | 20 | 80 | 0 | 3 |

#### 무공 경지 체계 [v1.0 신설]

| 경지 | 숙련도 | 설명 | 돌파에 필요한 최소 기연 등급 |
|------|--------|------|--------------------------|
| 입문 | 0~29 | 초식을 따라한다 | — |
| 숙련 | 30~59 | 초식이 자연스러워진다 | 전기(3개+) |
| 통달 | 60~89 | 초식을 넘어선 이해 | 기연(4개+) |
| 화경 | 90~100 | 무공이 몸의 일부 | 천재기연(5개만) |

#### 수련 효율 계수 체계 [v1.0 신설]

현재 구현된 공식:
```
성장량 = intensity × life_stage_multiplier
```

향후 확장 공식 (심리/관계/공간 도메인 구현 이후):
```
최종 성장량 = 기본량 × 생애단계 계수 × 감정 계수 × 성격 계수 × 장소 계수 × 관계 계수
```

이 계수들은 기연 시스템의 5가지 조건 판정에도 활용된다.

**전투력 계산**: 무력 + 경공 + 내공 (Iteration 2.1 단순 합산, 4.2에서 무공/장비 보정 추가)

**시간 도메인과의 관계**:
- YearPassed 이벤트 수신 → 나이에 따른 능력치 쇠퇴/성장 처리
- 지혜는 성장 도메인 소유 (심리 도메인 아님)

**[v1.0 구현 완료]**: GrowthProfile, StatBlock, StatType(9개), StatCategory(3개), calculate_training, calculate_yearly_aging. 189 tests 통과.  
**[v1.0 미구현]**: MartialArt, train_art, 부산물 효과, 최대 강도, 수련 효율 계수.

### 2.4 성장 도메인 확장 — 기연(奇緣) 시스템 [v1.0 신설]

> 성장이 폭발하는 순간에는 항상 **장소(탐험)**, **사람(관계)**, **마음 상태(심리)**가 얽혀 있다.

```
령호충이 독고구검을 깨우친 순간:
  혼자 수련?     아니요.
  어디서?        사과(思過)절벽 — 특수한 장소        ← 조건①
  누구와?        풍청양 — 스승과의 관계              ← 조건②
  뭘 가지고?     석벽의 검보 — 비급                  ← 조건③
  어떤 상태?     절망 속 결의 — 감정                 ← 조건④
  언제?          젊은 나이, 돌파 직전 — 시기          ← 조건⑤
```

#### 5가지 조건

| 조건 | 기호 | 단련 시 판정 | 연마 시 판정 |
|------|------|------------|------------|
| 장소(場) | ① | 해당 능력치 수련 보너스 장소? | 해당 무공 유형 보너스 장소? |
| 사람(人) | ② | 같이 단련하는 동료/경쟁자 | 해당 무공을 아는 고수/스승 |
| 아이템(物) | ③ | 영약, 보양식 | 비급, 무공서, 무기 |
| 감정(心) | ④ | 수련에 좋은 감정 (결의 등) | 무공 적합 감정 (독고구검↔평온) |
| 시기(時) | ⑤ | 나이/계절 보너스 | 숙련도 구간 돌파 시점 |

#### 순방향 조합 가중치 (기연)

| 순방향 조건 수 | 가중치 | 등급 | 발생 빈도 (체감) |
|--------------|--------|------|----------------|
| 1개 | ×1.0 | 일상(日常) | 매일 |
| 2개 | ×1.5 | 호기(好機) | 며칠에 한 번 |
| 3개 | ×2.5 | 전기(轉機) | 한 달에 한두 번 |
| 4개 | ×4.0 | 기연(奇緣) | 게임 전체에서 몇 번 |
| 5개 | ×7.0 | 천재기연(天載奇緣) | 평생 한두 번 |

#### 역방향 조합 가중치 (재앙)

| 역방향 조건 수 | 가중치 | 등급 |
|--------------|--------|------|
| 1개 | ×1.0 | 불운(不運) |
| 2개 | ×1.5 | 위기(危機) |
| 3개 | ×2.5 | 액운(厄運) |
| 4개 | ×4.0 | 대화(大禍) |
| 5개 | ×7.0 | 주화입마(走火入魔) |

#### 순역 혼합 판정

```
순 조건 수 = 순방향 개수 - 역방향 개수

양수 → 순방향 가중치 테이블 적용
음수 → 역방향 가중치 테이블 적용 (절대값으로)
0   → ×1.0 (상쇄)
```

#### 단련 기연 등급별 효과

| 등급 | 수치 효과 | 추가 효과 |
|------|----------|----------|
| 일상(1) | 기본 성장 | — |
| 호기(2) | ×1.5 성장 | — |
| 전기(3) | ×2.5 성장 | 추가 능력치 보너스 |
| 기연(4) | ×4.0 성장 | 피로 완전 회복 + 무공 비밀 특성 힌트 1개 |
| 천재기연(5) | ×7.0 성장 | 피로/부상 완전 회복 + 비밀 특성 완전 발견 + **능력치 상한 +5 (100→105)** |

#### 연마 기연 등급별 효과

| 등급 | 숙련도 효과 | 추가 효과 |
|------|-----------|----------|
| 일상(1) | 기본 상승 | — |
| 호기(2) | ×1.5 상승 | — |
| 전기(3) | ×2.5 상승 + 경지 돌파 가능 | 비밀 특성 힌트 1개 자동 발견 |
| 기연(4) | ×4.0 상승 + 경지 돌파 가능 | 비밀 특성 1개 완전 발견 + 관련 능력치 +5 + 새 초식 해금 |
| 천재기연(5) | ×7.0 상승 + 경지 돌파 확정 | 비밀 특성 전체 발견 + 피로/부상 회복 + **영구 전투 보너스(칭호/특성)** |

**단련 vs 연마 기연 비교**:
```
                    단련 기연              연마 기연
────────────────────────────────────────────────────
주 효과            능력치 대폭 상승        숙련도 대폭 상승
추가 효과          피로 회복              비밀 특성 발견
                   상한 돌파(100→105)    경지 돌파 (질적 변화)
영구 보너스         능력치 상한 +5         칭호/특성 획득
이야기 가치         낮음 (숫자 변화)       높음 (캐릭터 전환점)
```

**기연 발동 구조**:
```
5가지 조건 체크: 장소 + 사람 + 아이템 + 감정 + 시기
  │
  ├─ 순방향 많으면 → 기연 (성장 폭발 + 특별 보상)
  ├─ 역방향 많으면 → 재앙 (주화입마 등)
  └─ 섞여 있으면 → 상쇄 후 판정
```

### 2.5 관계 도메인 (Relationship) — [v2.2 2축 모델 변경]

> "두 사람 사이에 무엇이 있나?"  
> 비유: 강호 인맥첩 — 누구와 어떤 사이인지  
> 📎 수치/공식/이벤트 소스 상세: [relationship-mechanic.md](relationship-mechanic.md)

**소유 데이터**:
- 관계 유형 (사제, 연인, 적, 동료, 주인-동물 등)
- 호감도 (affinity: i16, -100 ~ +100) — 음수=적대, 양수=호감 [v2.2 변경: 3축→2축]
- 신뢰도 (trust: u8, 0 ~ 100) — 상승 느림, 하락 빠름
- 상호작용 기록 (언제, 무슨 일이 있었는지)

**3축→2축 변경 이유** [v2.2]:
- 호감도/적대도 분리 시 "호감 높고 적대 높은" 모호한 상태 발생
- NPC AI(Gemma 4B)가 3축 동시 판단 비현실적
- 호감도를 -100~+100으로 확장하면 적대를 음수로 자연 표현

**관계 변화 — 12개 이벤트 소스 (MVP 3개)**:
- ✅ 대화(Conversation): 호감도만 변경 — 임베딩 감정 분석 + LLM 판정
- ✅ 시간(Time): 호감도/신뢰도 감쇠
- ✅ 관찰(Observation): 호감도 변경
- 향후: 전투, 구출, 배반, 선물, 함께수련, 간호, 조직, 거래, 동행
- 📎 이벤트별 상세: [relationship-mechanic.md](relationship-mechanic.md) §3~§6

**대화 이벤트 메카니즘** [v2.2 변경]:
- [affinity: N] LLM 태그 방식 **폐기** (Gemma 4B/12B 태그 품질 신뢰 불가)
- 매 턴: 임베딩 감정 분석 (~28ms, 소폭 ±1~3)
- 특정 시점: 감정 누적 임계치 도달 OR 대화 종료 시 LLM 판정 (±1~10)
- 📎 상세: [relationship-mechanic.md](relationship-mechanic.md) §4

**관계가 성장에 미치는 영향** [v1.0 신설]:
```
동료와 같이 단련 → 기연 조건② 충족, 수련 효율 관계 계수↑
스승에게 배움     → 기연 조건② 충족 (연마), 경지 돌파 확률↑
연인과 함께 휴식  → 피로 회복 -20/일 (관계 피로 회복)
적대자 근처 체류  → 피로 +5/일 (긴장) [적대 = 호감도 -40 이하]
동료/연인 간호    → 부상 회복 단축 + 호감도/신뢰도 상승
```

**배반 감지**:
- 심리 도메인의 가치관 + 관계 도메인의 호감도(음수 영역)를 조합하여 판단
- 야망(높음) + 충성(낮음) + 호감도(음수) = 배반 위험

### 2.7 공간 도메인 (Space) — [v1.0 수련/회복 연동 추가]

> "그곳은 어디에 있고 뭐가 있나?"  
> 비유: 강호 지도 — 물리적 장소와 거리

**소유 데이터**:
- 장소 (Location)
  - 유형: 수도, 도시, 마을, 산, 사찰, 장원, 황야, 교역소, 전장
  - 좌표 (x, y)
  - 소속 국가 (NationId 참조)
- 지형 특성 (전투 보너스, 이동 비용)
- 이동 경로 (장소 간 거리, 이동 수단별 소요 시간)
- **수련 보너스 장소 정보** [v1.0 추가]
- **피로 회복 장소 정보** [v1.0 추가]

**공간 도메인과 성장의 연결** [v1.0 신설]:
```
장소가 수련에 미치는 영향:
  무당산 → 내공 수련 보너스 장소      ← 기연 조건①
  화산   → 검법 연마 보너스 장소      ← 기연 조건①
  소림사 → 권법/내공 보너스           ← 기연 조건①
  황야   → 보너스 없음, 위험 높음

장소가 피로 회복에 미치는 영향:
  온천     → -20/일
  약초밭   → -15/일
  사찰/도관 → -15/일
  자기 문파 → -12/일
  객잔     → -10/일
  야외 노숙 → -3/일
```

**세계관 도메인과의 분리 이유**:
- 세계관: "화산파는 정파 구파일방 중 하나다" (조직)
- 공간: "화산파 본거지는 화산(華山)에 있다" (장소)
- 변화 주기가 다름: 조직 구조는 드물게, 지형은 이벤트에 따라 변함

**여러 도메인이 참조**:
- 전투: "이 지형에서 경공이 유리한가?"
- 경제: "교역로 거리 계산"
- 시간: "이동에 며칠 걸리나"
- 서사: "절벽에서 떨어지는 이벤트"
- **성장: "이 장소에서 수련 보너스가 있나?" (기연 조건①)** [v1.0 추가]
- **캐릭터: "이 장소에서 피로가 얼마나 회복되나?"** [v1.0 추가]

### 2.11 시간 도메인 (Time) — [v1.1 시간대(Watch) 시스템 추가]

> "지금은 언제인가?"  
> 비유: 강호의 달력 — 시간의 흐름이 세계를 움직인다

**소유 데이터**:
- 게임 시간 (연/월/일/**시간대**)
- 계절 (봄/여름/가을/겨울)
- 시간대 (Watch/經): 6시간대, 십이시진 2개 묶음 [v1.1 확장]
- 예약 이벤트 스케줄

**시간대(Watch/經) 체계** [v1.1 신설]:
```
시간대          시진              현대 시간     특징
─────────────────────────────────────────────────────
Dawn(黎明)     인시~묘시(寅卯)    03~07시     내공 수련 보너스, 하루의 시작
Morning(午前)  진시~사시(辰巳)    07~11시     탐험/거래/이동 최적
Midday(正午)   오시~미시(午未)    11~15시     외공/무력 수련 보너스, 양기 절정
Afternoon(午後) 신시~유시(申酉)   15~19시     지적 활동/연마 보너스
Evening(黃昏)  술시~해시(戌亥)    19~23시     휴식/관계 형성, 피로 회복
Night(深夜)    자시~축시(子丑)    23~03시     수면/비밀 행동, 사파무공 보너스

1 tick = 1 시간대(Watch)
6 tick = 1일
2160 tick = 1년 (360일 × 6시간대)
```

**시간 이벤트 발행** [v1.1 확장]:
```
시간 도메인이 tick()할 때마다:

  "WatchChanged" 발행 [v1.1 신설]     — 매 tick
     │
     └──▶ (향후) 시간대별 수련 보너스 적용
          시간대별 NPC 행동 패턴 변경

  "DayPassed" 발행 [Night→Dawn 전환 시] — 매 6 tick
     │
     ├──▶ 캐릭터: 피로 자연 회복 (-5 수면)
     ├──▶ 캐릭터: 부상 회복 진행
     └──▶ 성장: 일일 수련 결과 적용

  "SeasonChanged" 발행                 — 연 4회
  "YearPassed" 발행                    — 연 1회
     │
     ├──▶ 캐릭터: 나이 +1
     ├──▶ 성장: 체력 쇠퇴, 지혜 성장
     ├──▶ 심리: 성격 미세 변화
     ├──▶ 관계: 오래된 관계 변화
     └──▶ 세계관: 왕조 수명, 문파 역사
```

**행동 방식 — "묘시까지 수련한다"** [v1.1 신설]:
```
플레이어: "진시(Morning)까지 내공 수련"
    │
    └─→ tick_until(Watch::Morning)
        └─→ Dawn 1 tick 소비 → WatchChanged(Morning)
            └─→ 수련 결과 계산 (새벽 내공 보너스 ×1.2)

매 시간대 결정이 아닌, "언제까지 무엇을 한다" 방식.
특별한 선택이 없으면 Night는 자동 수면 처리.
```

**시간대별 수련 보너스** [v1.1 기연 시스템 '時' 조건 기반]:
```
Dawn + 내공 수련 → ×1.2    (양기 상승기)
Midday + 외공/무력 → ×1.2   (양기 절정)
Afternoon + 지적 활동 → ×1.2 (차분한 시간)
Night + 사파 무공 → ×1.3    (음기 최고)
Night + 정파 내공 → ×0.8    (기가 흐트러짐)
```

**예약 이벤트 (스케줄러)**:
- "3년 후" → 화산논검대회
- "보름달" → 일월신교 의식
- "10년 후" → 스승의 복수 기한

**시간 도메인이 존재하는 이유**:
- 시간 도메인 없이는 게임 루프가 "누구에게 시간을 알려야 하는지" 다 알아야 함
- 시간 도메인이 있으면 각 도메인은 자기가 관심 있는 시간 이벤트만 구독

**[v1.0 구현 완료]**: GameClock, TimeEvent enum, 360일/년 체계 구현됨.
**[v1.1 구현 예정]**: Watch enum, WatchChanged 이벤트, tick() 시간대 단위 전환, tick_until()/tick_day() 편의 메서드.

### 2.12 사물 도메인 (Item) — [v1.0 피로/기연 연동 추가]

> "이것은 무엇인가?"  
> 비유: 강호의 물건들 — 세계에 존재하는 사물

**소유 데이터**:
- ItemId (고유 식별자)
- 이름, 설명
- 종류: 무기 / 의복 / 음식 / 서적(비급) / 약물 / 기타
- 기본 속성 (무게, 희귀도)

**하나의 물건이 여러 도메인에서 다른 의미**:
- 경제: "녹파검은 3000냥짜리"
- 전투: "공격력 +30"
- 서사: "청성파의 상징, 퀘스트 열쇠"
- 관계: "이걸 선물하면 호감도 +50"
- **성장: "비급은 기연 조건③, 영약은 단련 보너스"** [v1.0 추가]
- **캐릭터: "영약은 피로 -15 즉시, 상급 영약은 -30"** [v1.0 추가]

**동물은 사물이 아닌 캐릭터**:
- 신조(神鵰), 한혈보마(汗血寶馬) 등은 캐릭터 도메인의 Companion 역할
- 감정/성장/관계/사망이 있으므로 사물과 성격이 다름

### 2.13 기억 도메인 (Memory) — [v2.1 독립 도메인 승격]

> "이 NPC는 무엇을 기억하나?"  
> 비유: 기억 서고(記憶書庫) — NPC가 겪고, 생각하고, 계획한 것의 저장소

**독립 배경**: 기존에는 심리 도메인(§2.2)의 하위 항목("향후 구현")이었으나, 구현 결과 독자적인 데이터·포트·이벤트·검색 알고리즘을 가진 완전한 도메인 경계를 형성하므로 12번째 도메인으로 승격한다.

**소유 데이터**:
- MemoryEntry — 기억 항목 (관찰 / 성찰 / 계획)
- 중요도 (1~10), 키워드, 언어 코드, 성찰 트리 (source_ids)
- ScoredMemory — 벡터 유사도 점수 포함 기억
- RankedMemory — 4축 종합 점수(최신성·중요도·관련도·감정일치) 포함 기억

**이벤트 (MemoryEvent)**:
- MemoryStored — 기억이 저장됨
- MemoryRecalled — 기억이 회상됨
- ImportanceUpdated — 중요도가 변경됨

**포트 (Output Port)**:
- MemoryRepository — 기억 저장, 검색, 조회, 중요도 갱신
- EmbeddingPort — 텍스트 → 벡터 변환 (비대칭 모델 지원)

**심리 도메인과의 관계**:
- 심리 도메인이 "성찰이 필요하다"고 판단 → 기억 도메인에서 관련 기억 검색 → LLM이 성찰 수행 → 결과를 기억 도메인에 저장
- OCC 감정 상태가 기억 검색 시 감정 일치도(emotional_match) 가중치로 작용

**📎 상세 설계**: [memory-domain-analysis.md](memory-domain-analysis.md)  
**📎 구현 아키텍처**: [npc-conversation-memory-architecture.md](../ai/npc-conversation-memory-architecture.md)

### 3.2 이벤트 흐름

도메인 간 통신은 **도메인 이벤트**로 이루어진다.

**이벤트 구조**: 각 도메인이 자기 이벤트 enum을 소유하고, DomainEvent wrapper가 감싼다.

```rust
// 도메인별 이벤트 enum (각 도메인이 소유)
TimeEvent::YearPassed { new_year }
TimeEvent::DayPassed { day }
CharacterEvent::Aged { character_id, new_age }
CharacterEvent::FatigueChanged { character_id, new_fatigue }
CharacterEvent::Injured { character_id, injury }

// Wrapper enum (Application Service에서 사용)
DomainEvent::Time(TimeEvent::YearPassed { .. })
DomainEvent::Character(CharacterEvent::Aged { .. })
```

```
[시간] ──TimeEvent::YearPassed──▶ [캐릭터] 나이+1
                                   [성장] 쇠퇴/성장
                                   [심리] 성격변화
                                   [관계] 소원해짐

[시간] ──TimeEvent::DayPassed──▶ [캐릭터] 피로 자연회복, 부상 진행

[심리] ──PsychologyEvent::EmotionChanged──▶ [서사] 스토리 분기 판단
                                             [전투] 전투 중 감정 영향
                                             [성장] 수련 효율 계수 변경

[관계] ──RelationshipEvent::ConflictErupted──▶ [서사] 갈등 이벤트 생성
                                                [심리] 감정 변화

[서사] ──NarrativeEvent::QuestTriggered──▶ [전투] 전투 시작
                                           [경제] 보상 지급

[성장] ──GrowthEvent::FortuneTriggered──▶ [서사] 기연 이벤트 생성
                                           [캐릭터] 피로/부상 회복 (기연 4+)
```

### 3.3 성장-탐험-관계 순환 구조 [v1.0 신설]

```
탐험 → 장소 발견 (수련 보너스, 비급)
  ↓
성장 (단련/연마, 기연 가능)
  ↓
강해짐 → 새 곳 탐험 가능, 무공 습득
  ↓
관계 (같이 수련→호감↑, 간호→신뢰↑)
  ↓
동료와 함께 → 더 먼 곳, 스승 소개, 기연 조건↑
  ↓
탐험 (순환)
```

### 3.4 피로 순환 구조 [v1.0 신설]

```
수련 → 능력치/숙련도 ↑ + 피로 ↑
  │
  ├─ 피로 적으면 → 내일도 수련 가능
  │
  ├─ 피로 많으면 → 며칠 쉬어야 함
  │   ├─ 쉬면서 탐험  → 장소 발견
  │   ├─ 쉬면서 관계  → 호감도 상승
  │   └─ 장소/사람/아이템으로 빠른 회복
  │
  └─ 부상 나면 → 치료 필요
      ├─ 혼자 (느림)
      ├─ 의원 (빠름, 돈)
      └─ 동료/연인 간호 (관계 발전 계기)
```

### 3.5 LLM Adapter의 위치

```
LLM Adapter는 도메인이 아니라 인프라이다.

  심리 도메인: "반성을 생성해야 한다"
       │
       ▼  (Outbound Port: trait LlmPort)
  LLM Adapter: 프롬프트 조립 → LLM 호출 → 응답 파싱
       │
       ▼
  심리 도메인: 결과를 기억 스트림에 저장

프롬프트 조립 시 여러 도메인에서 데이터를 읽음:
  심리 → 성격/가치관/감정/기억
  성장 → 능력치, 무공 경지
  관계 → 호감도/적대도
  세계관 → 소속 문파
  캐릭터 → 피로/부상 상태
```

## 4. Hexagonal Architecture 적용

### 4.1 계층 구조

```
  Driving Adapters (외부 → 도메인)
  ├── ECS 게임엔진 System
  ├── CLI (테스트/디버그)
  └── Test Harness
         │
    Inbound Ports (trait: 서비스 인터페이스)
         │
    Domain Core (순수 Rust, 외부 의존성 없음)
    ├── Model: Entity, Value Object, Aggregate Root
    ├── Service: 비즈니스 로직 조합
    └── Event: 도메인 이벤트
         │
    Outbound Ports (trait: 도메인이 필요로 하는 것)
         │
  Driven Adapters (도메인 → 외부)
  ├── InMemory (테스트용)
  ├── 벡터DB (프로덕션)
  └── Local LLM
```

### 4.2 테스트 전략

```
테스트 시: InMemory Adapter를 주입
  → DB 없이 도메인 로직 검증 가능
  → LLM 없이 감정/기억 로직 검증 가능

프로덕션 시: 실제 Adapter를 주입
  → 벡터DB로 벡터 검색
  → Local LLM으로 추론
  → ECS 게임엔진으로 게임 루프 연결
```

## 5. 게임 설정 요약

### 5.1 세계관 구조

- 국가: 7개 (왕조 4 + 공화국 1 + 부족연합 1 + 자치령 1)
- 무림: 정파 구파일방(10) + 사파(3)
- 상인: 상방 체계
- 화폐: 냥(兩)

### 5.2 캐릭터 시스템

- 역할: Player / NPC / Companion(동물)
- 생애 단계: 청년(~32) → 장년(33~54) → 중년(55~68) → 노년(69~)
- **신체 상태**: 피로(0~100), 부상(Option) [v1.0 추가]
- **능력(能)** — 성장 도메인 소유:
  - 지적: 내공/지혜/책략 (u32, 0~100)
  - 육체: 체력/경공/무력 (u32, 0~100)
  - 감정: 의지/인내/공감 (u32, 0~100)
- **성향(性)** — 심리/성격 Aggregate (①층) 소유:
  - Big Five: 개방성/성실성/외향성/친화성/신경증 (f32, 0.0~1.0)
- **서사(敍)** — 심리/3축 가치관 Aggregate (②층) 소유 [v1.5 신규]:
  - 3축: 믿음(信)/옳음(正)/바람(願) (각 축 = 강도 f32 + 신조 텍스트)
  - LLM 프롬프트 전용, OCC 수식에 직접 투입되지 않음
- **판단(判)** — 심리/5가치 Aggregate (③층) 소유 [v1.5 역할 재정의]:
  - 5가치: 충/의/효/복수/야망 (f32, 0.0~1.0)
  - OCC 감정 평가 수식의 직접 입력 (코드 처리)
- **감정/기분** — 심리/감정 (④⑤층) 소유 [v1.5 설계 완료]:
  - OCC 22종 인지평가 → PAD 3차원 기분 상태
  - 📎 상세: [occ-emotion-detail.md](../psychology/occ-emotion-detail.md)

### 5.3 성장 시스템 [v1.0 대폭 확장]

- **단련(鍛鍊)**: 능력치 집중 성장 (`train_stat()`)
- **연마(練磨)**: 무공 숙련도 성장 + 부산물 능력치 (`train_art()`)
- **무공 경지**: 입문 → 숙련 → 통달 → 화경
- **기연 시스템**: 장소×사람×아이템×감정×시기 조합으로 폭발적 성장 또는 재앙
- **최대 강도**: 체력+인내+의지로 결정, 피로로 감소
- **피로 순환**: 수련→피로↑→휴식/탐험/관계→피로↓→수련 (성장-탐험-관계 순환의 핵심)

### 5.4 NPC AI 시스템 [v1.5 7층 아키텍처 반영]

- **7층 심리 아키텍처**: 성격(①) → 3축가치관(②) → 5가치(③) → 감정(④) → 기분(⑤) → 행동(⑥) → 성찰(⑦)
- 성격: HEXACO 6요인 (기질적 토대, 거의 불변, 나이 drift 없음) [v2.0]
- 가치관: 3축(LLM 서사) ↔ 5가치(OCC 수식) — 성찰을 통한 양방향 해석 관계
- 감정: OCC 22종 (코드 <1ms) → PAD 3차원 기분 (렌즈 역할)
- 행동: Utility AI (코드) → LLM (구체적 대사/행동)
- 성찰: Tier 1~4 (순간반응 ~ 인생성찰), LLM이 가치관/신조 변화 판단
- 기억: Stanford Generative Agents (관찰/반성/계획), 벡터DB 검색
- 추론: Local LLM (성찰/대사/행동 생성)
- 📎 전체 상세: [npc-psychology-architecture.md](../psychology/npc-psychology-architecture.md)
