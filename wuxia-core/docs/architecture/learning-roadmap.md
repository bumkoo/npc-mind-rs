## 3. 영역 1: 게임 스토리와 세계관 — 인문학적 기반

### 3.1 개념: 왜 인문학이 필요한가?

무협 RPG의 세계관은 "가짜 역사"를 만드는 일입니다. 진짜처럼 느껴지려면 실제 역사·문학·철학의 뼈대가 필요합니다.

```
예제: 와호장룡(臥虎藏龍)의 인문학적 층위

┌─ 역사적 층위 ──────────────────────────────┐
│  청나라 건륭제 시대 배경                      │
│  → 만주족 vs 한족 긴장                       │
│  → "누가 진짜 중국의 주인인가?"              │
└──────────────────────────────────────────────┘
         │
         ▼
┌─ 철학적 층위 ──────────────────────────────┐
│  도가: 이모배(李慕白)의 "놓아줌"             │
│        → 검을 내려놓으려 하지만 못함          │
│  유가: 의무와 개인 욕망의 충돌                │
│        → 옥교룡(玉嬌龍)이 규범을 거부        │
│  불가: 집착이 고통의 원인                     │
│        → 이모배의 비극적 결말                 │
└──────────────────────────────────────────────┘
         │
         ▼
┌─ 문학적 층위 ──────────────────────────────┐
│  협의: "큰 것을 위해 작은 나를 희생"         │
│  복수: 벽안호(碧眼狐)의 원한이 세대를 넘음    │
│  성장: 옥교룡이 자유를 찾아가는 여정          │
└──────────────────────────────────────────────┘
```

### 3.3 세계관 구축의 5가지 기둥

```
기둥 1: 권력 구조
─────────────────────────────────────────
  "누가 힘을 가지고 있는가?"

  예제 — 칠국춘추:
  ┌── 조정(朝廷) ──── 7개 국가의 정치 권력
  ├── 무림(武林) ──── 구파일방 + 사파 3파벌
  ├── 상방(商邦) ──── 경제적 권력
  └── 암흑(暗黑) ──── 혈교 잔당, 지하 세력

  핵심 질문: 이 네 세력이 충돌할 때 무슨 일이 벌어지는가?


기둥 2: 가치 체계
─────────────────────────────────────────
  "이 세계의 사람들은 무엇이 옳다고 믿는가?"

  예제 — 칠국춘추 5축 가치관:
  충(忠) ─── "나라/조직에 대한 충성"
  의(義) ─── "약자를 돕는 정의감"
  효(孝) ─── "스승과 부모에 대한 예"
  복수 ──── "원한을 갚아야 하는가?"
  야망 ──── "더 높이 올라가고 싶은 욕망"

  예제 — 인물별 차이:
  남궁혁(검왕): 충=0.9  의=0.3  → "나라를 위해서라면 무고한 자도 벤다"
  소연:         충=0.2  의=0.8  → "사람이 먼저, 조직은 나중"
  → 같은 사건을 놓고 정반대 행동 → 갈등 발생!


기둥 3: 기술 체계 (무공)
─────────────────────────────────────────
  "이 세계의 힘은 어떻게 작동하는가?"

  예제 — 무공 경지 4단계:
  입문(入門) → 숙련(熟練) → 통달(通達) → 화경(化境)

  아스키 그림으로 보는 수련 곡선:
  능력
   │          ╱ 화경 (극소수 도달)
   │        ╱
   │      ╱ 통달 (오랜 수련 + 깨달음)
   │    ╱
   │  ╱ 숙련 (꾸준한 노력)
   │╱
   └─────────────── 시간 (년)
     입문
     (빠름)

  핵심: 각 단계 사이에 "벽"이 있음 → 게임의 도전 요소


기둥 4: 지리와 공간
─────────────────────────────────────────
  "어디에서 무슨 일이 벌어지는가?"

  예제 — 칠국 배치 (개념도):
  ┌─────────────────────────────────────┐
  │              북원(北原)              │
  │              [왕조·유목]             │
  │                                     │
  │  서량(西涼)     대진(大辰)     동해(東海)│
  │  [왕조·군사]   [왕조·수도]   [공화국]  │
  │                                     │
  │         자유도시                     │
  │         [자치령]                     │
  │                                     │
  │         남궁(南宮)                   │
  │         [왕조·가문]                  │
  │                                     │
  │   남만(南蠻)          해상 교역로     │
  │   [부족연합]                        │
  └─────────────────────────────────────┘

  각 지역마다 고유한 갈등, 문화, 무공 유파가 존재


기둥 5: 시간과 역사
─────────────────────────────────────────
  "과거에 무슨 일이 있었고, 지금에 어떤 영향을 미치는가?"

  예제 — 칠국춘추 270년 역사 중 핵심:
  [30년 전] 영웅이 혈교를 막음 → 그 영웅이 타락
  [10년 전] 붉은 밤의 변 → 화산파 멸문
  [현재]    17세 생존자가 강호에 첫 발을 내딛음

  핵심: 과거의 선택이 현재의 갈등을 만듦
```

### 4.2 도구별 학습 로드맵

#### 4.2.1 Rust (현재 수준: 중급)

```
현재 할 수 있는 것                  다음에 배울 것
──────────────────────────────────────────────────
✅ struct, enum, impl              async/await (LLM 호출)
✅ trait (Port 패턴)               trait object vs generic
✅ 모듈 시스템                     에러 처리 전략 (thiserror)
✅ 테스트 작성                     벤치마크 (criterion)
✅ serde 직렬화                    FFI (LLM 연동)
```

```rust
// 예제: 현재 구현된 패턴 (wuxia-core의 Port trait)
// 이것이 LLM Adapter의 기초가 됨

/// LLM에게 요청을 보내는 인터페이스 (순수 도메인 측)
pub trait LlmPort {
    /// NPC의 기억 중요도를 1~10으로 평가
    fn evaluate_importance(&self, memory_text: &str) -> Result<u8, LlmError>;

    /// NPC의 일일 계획을 생성
    fn generate_plan(&self, context: &NpcContext) -> Result<DailyPlan, LlmError>;

    /// 두 NPC 간 대화를 생성
    fn generate_dialogue(
        &self,
        speaker: &NpcContext,
        listener: &NpcContext,
        topic: &str,
    ) -> Result<String, LlmError>;
}

// 테스트에서는 MockLlm으로, 실제에서는 LlamaLlm으로 교체
// → 이것이 "순수 로직 + 어댑터" 패턴의 핵심
```

```
                    └─────────────────────────────┘
```

```rust
// 예제: ECS System의 기본 형태
// Phase 5에서 구현할 코드의 미리보기

use bevy::prelude::*;
use wuxia_core::growth::GrowthProfile;
use wuxia_core::character::Character;
use wuxia_core::time::GameClock;

/// 매 게임 년(Year)이 지날 때 노화를 적용하는 시스템
fn aging_system(
    mut query: Query<(&mut GrowthProfile, &Character)>,
    clock: Res<GameClock>,
    mut year_events: EventReader<YearChangedEvent>,
) {
    for _event in year_events.read() {
        for (mut growth, character) in query.iter_mut() {
            // wuxia-core의 순수 함수 호출
            let aging_result = growth.calculate_yearly_aging(
                character.age(),
                character.life_stage(),
            );
            growth.apply_aging(aging_result);
        }
    }
}
```

## 5. 영역 3: 게임 스토리 창작

### 5.1 개념: 게임 스토리 ≠ 소설 스토리

```
소설 스토리                         게임 스토리
──────────────────────────────────────────────────
작가가 모든 것을 결정                플레이어가 선택함
선형 진행                           분기와 결과
독자는 관찰자                       플레이어는 참여자
감정이입은 묘사로                    감정이입은 행동으로

예제 비교:

  소설(청강만리):
  "그는 칼을 뽑았다. 오랜 망설임 끝에."
  → 독자는 읽고 공감

  게임(칠국춘추):
  [상황] 스승의 원수가 눈앞에 있다. 그러나 그에게는 어린 딸이 있다.
  [선택지]
    A. 복수한다 → 복수 가치관 ↑, 의리 ↓, 딸이 새로운 원한의 씨앗
    B. 놓아준다 → 의리 ↑, 복수 ↓, 스승의 영혼은 편안할까?
    C. 사실을 알린다 → "네 아버지가 한 일을 알아야 한다"
  → 플레이어는 선택하고 결과를 경험
```

### 5.2 갈등 설계 프레임워크

```
갈등의 5가지 유형 (칠국춘추 예제)

유형 1: 인물 vs 인물
─────────────────────────────
  남궁혁(검왕) vs 소연
  "국가를 위한 충성" vs "개인의 정의"
  → 같은 사건에서 정반대 행동

유형 2: 인물 vs 자기 자신
─────────────────────────────
  플레이어: 화산파 멸문의 생존자
  "복수해야 하는가?" vs "새로운 삶을 살아야 하는가?"
  → 내면의 갈등이 성장을 이끔

유형 3: 인물 vs 조직
─────────────────────────────
  당무괴(독왕): 사파 소속이지만 자기만의 길
  "조직의 명령" vs "나의 연구"
  → 조직에서 이탈하는 순간

유형 4: 조직 vs 조직
─────────────────────────────
  대진(왕조) vs 동해(공화국)
  "잃어버린 영토" vs "독립 수호"
  → 국가 간 전쟁의 위기

유형 5: 인물 vs 세계의 규칙
─────────────────────────────
  "무공이 강해질수록 인간성을 잃는다" (주화입마)
  → 성장의 대가, 시스템 자체가 갈등
```

### 5.3 NPC 자율 스토리 생성 — AI가 만드는 이야기

```
플레이어가 행동하지 않아도 NPC끼리 이야기가 진행됨

예제 시나리오: "소문의 확산"

  Day 1: NPC_A(상인)가 자유도시에서 정보를 들음
         "대진이 군대를 모으고 있다"
         → Memory에 저장, importance: 8

  Day 3: NPC_A가 NPC_B(무인)를 만남
         → 기억 검색 → 관련 기억 발견
         → LLM이 대화 생성: "형, 큰일이야. 대진이..."
         → NPC_B Memory에도 저장

  Day 5: NPC_B가 NPC_C(문파 장로)에게 보고
         → 정보가 변형됨 (전화놀이 효과)
         → NPC_C가 문파 회의를 소집

  Day 7: 플레이어가 그 문파를 방문
         → "최근 분위기가 심상치 않다"
         → 플레이어는 이미 진행 중인 사건에 합류

  ┌─────────────────────────────────────────┐
  │  이것이 Generative Agents의 "창발적      │
  │  사회 행동"이며, 칠국춘추가 목표로 하는   │
  │  NPC 자율 스토리의 핵심                   │
  └─────────────────────────────────────────┘
```

### 5.4 학습 과제

| 순번 | 과제 | 구체적 행동 | 산출물 |
|------|------|-------------|--------|
| 3-1 | 갈등 매트릭스 작성 | 기존 NPC 6명의 갈등 관계 정리 | 갈등 관계도 |
| 3-2 | 분기 시나리오 1개 | "첫 만남" 이벤트의 3가지 결과 설계 | 분기 흐름도 |
| 3-3 | NPC 대화 프롬프트 | Generative Agents 패턴으로 프롬프트 작성 | 프롬프트 템플릿 |
| 3-4 | 소문 확산 시나리오 | 정보가 5명의 NPC를 거치며 변형되는 시나리오 | 시나리오 문서 |
| 3-5 | 플레이어 서사 아크 | 17세→30대까지의 핵심 전환점 5개 | 서사 아크 문서 |

## 7. 영역 5: 게임 메카닉 정의

### 7.1 개념: 게임 메카닉이란?

```
게임 메카닉 = "플레이어가 할 수 있는 행동"과 "그 행동의 결과를 결정하는 규칙"

예제 — 칠국춘추의 핵심 메카닉 순환:

  ┌─────────┐     ┌─────────┐     ┌─────────┐
  │  성장    │────►│  탐험    │────►│  관계    │
  │ (수련)   │     │ (이동)   │     │ (대화)   │
  └────┬────┘     └────┬────┘     └────┬────┘
       │               │               │
       │    능력↑       │   장소 발견    │   호감도↑
       │    피로↑       │   비급 획득    │   동맹 형성
       │               │               │
       └───────────────┴───────────────┘
                       │
              ┌────────▼────────┐
              │   전투 (선택적)  │
              │   → 무공 사용    │
              │   → 승/패/부상   │
              └─────────────────┘
```

### 7.2 이미 설계된 메카닉 (요약)

```
메카닉                 상태    핵심 규칙
──────────────────────────────────────────────────────
단련(train_stat)       ✅     능력치 직접 성장, 강도 조절 가능
연마(train_art)        설계    무공 숙련도 + 능력치 부산물
노화(aging)            ✅     나이별 성장/쇠퇴 곡선
피로(fatigue)          설계    수련→피로↑→휴식 필요
부상(injury)           설계    전투/과수련으로 발생
기연(fortune)          설계    5조건(장소×사람×아이템×감정×시기)
무공 경지              설계    입문→숙련→통달→화경
시간(Watch)            ✅     6시간대, 시간별 수련 보너스
```

### 7.3 메카닉 설계 원칙

```
원칙 1: 선택에는 반드시 대가가 있다 (Trade-off)
───────────────────────────────────────────
  예: 수련 강도를 높이면?
    → 성장 속도 ↑ + 피로 ↑ + 부상 확률 ↑
    → "빨리 강해질까, 안전하게 갈까?"

원칙 2: 시스템끼리 연결되어야 한다 (Interconnection)
───────────────────────────────────────────
  예: 성장 ↔ 관계 연결:
    → 함께 수련하면 호감도 ↑ + 효율 ↑
    → 혼자 수련하면 호감도 변화 없음 + 집중력 ↑
    → "동료와 함께할까, 혼자 할까?"

원칙 3: 플레이어 행동이 NPC에게 영향 (Ripple Effect)
───────────────────────────────────────────
  예: 플레이어가 사파 인물을 도우면?
    → 사파 호감도 ↑ + 정파 호감도 ↓
    → 정파 NPC가 플레이어를 의심하기 시작
    → 기존 동맹이 흔들림
    → "한 명을 도우면 다른 한 명을 잃을 수 있다"
```

### 7.4 학습 과제

| 순번 | 과제 | 구체적 행동 | 산출물 |
|------|------|-------------|--------|
| 5-1 | 메카닉 흐름도 | 성장-탐험-관계 순환을 상세 흐름도로 | 메카닉 흐름도 |
| 5-2 | 밸런스 스프레드시트 | 능력치별 성장률, 쇠퇴율 수치 테이블 | 밸런스 시트 |
| 5-3 | 전투 메카닉 설계 | 전투 판정 공식 (공격력, 방어력, 무공) | 전투 공식 문서 |
| 5-4 | 경제 메카닉 설계 | 물가, 보수, 아이템 가격 체계 | 경제 밸런스 시트 |
| 5-5 | 기연 시나리오 3개 | 5조건 조합별 기연 시나리오 | 기연 사례집 |

## 10. 개발 원칙과 작업 방식

### 10.1 Iterative 개발 원칙

```
매 반복(Iteration)마다:

  1. 설계    → "이번에 무엇을 만들 것인가?"
  2. 구현    → "작동하는 작은 코드"
  3. 테스트  → "cargo test 통과"
  4. 리뷰    → "Claude와 코드 구조 검토"
  5. 문서화  → "Obsidian vault 업데이트"

  ⚠️ 코드 생성 전 반드시 구조 리뷰!
  ⚠️ Context7에서 최신 라이브러리 확인!
  ⚠️ Rust 로컬 컴파일 기준 (버전은 architecture-decision §4 참조)!
```

### 10.2 소스코드 작성 규칙

```
규칙 1: 코드 구조를 먼저 리뷰받는다
─────────────────────────────────────
  Claude: "이런 구조로 만들까요?"
  Bekay:  "좋아요" 또는 "이 부분 바꿔주세요"
  Claude: (승인 후) 코드 작성

규칙 2: 작동하는 작은 부분부터
─────────────────────────────────────
  Iteration 2.3 예시:
    Step 1: train 함수 이름만 변경 → 테스트 통과 확인
    Step 2: MartialArt struct 추가 → 테스트 작성
    Step 3: train_art 빈 함수 → 테스트 추가
    Step 4: train_art 로직 구현 → 테스트 통과

규칙 3: Claude 환경 제약 시 알려주기
─────────────────────────────────────
  Claude의 Rust 버전이 1.93보다 낮을 수 있음
  → 코드 다운그레이드하지 않고 먼저 알림
  → Bekay가 로컬에서 컴파일 결과 공유

규칙 4: Context7에서 최신 API 확인
─────────────────────────────────────
  ECS 게임엔진, 벡터DB 등의 API가 자주 변경됨
  → 코드 작성 전 반드시 최신 문서 확인
```
