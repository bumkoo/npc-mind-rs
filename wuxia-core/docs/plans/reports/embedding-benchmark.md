## 2. 테스트 설계

### 2.1 테스트 문장 구성 (v0.4.0, 총 56문장)

v2.0에서는 EN/ZH orig·short 문장을 대폭 보강하여, 각 언어가 독립적으로 4단계 GAP 분석이 가능하도록 균형을 맞추었다. v1.0 대비 23문장이 추가되었다.

```
          Group A(혈교)   Group B(소연)   Group C(무공)   Unrelated
          org sht lng     org sht lng     org sht lng     org sht
KO         2   2   2       2   2   2       2   2   2       2   2
EN         2   2   0       2   2   0       2   2   0       2   2
ZH         2   2   0       2   2   0       2   2   0       2   2
```

각 언어에서 독립적으로 측정 가능한 페어링 수는 다음과 같다. Level 1(orig↔orig): 그룹당 1쌍 × 3그룹 = 3쌍. Level 2(orig↔short): 그룹당 4쌍 × 3그룹 = 12쌍. Level 3(cross-group): 그룹 조합당 4쌍 × 3조합 = 12쌍. Level 4(unrelated): 그룹orig 6개 × 2unrel = 12쌍.

### 2.2 평가 프레임워크: 4단계 GAP 모델

v1.0의 단순 "그룹 내 vs 비관련" 비교를 넘어, 4개 수준의 의미적 거리를 측정하는 GAP 프레임워크를 도입했다.

```
  Level 1  Intra-Orig   같은 주제, 직접 표현     (orig ↔ orig)
  Level 2  Intra-Para   같은 주제, 의역 표현     (orig ↔ short)
  Level 3  Cross-Group  같은 세계관, 다른 주제   (그룹A ↔ 그룹B)
  Level 4  Unrelated    완전히 다른 도메인       (무협 ↔ 날씨/음식)

  이상적 분포: L1 > L2 >> L3 > L4
```

4개의 GAP을 정의했다.

```
  Gap α = L1 - L2   의역 인식력      (작을수록 좋음)
  Gap β = L2 - L3   ★ 주제 분리력    (클수록 좋음)
  Gap γ = L3 - L4   세계관 문맥 인식  (양수면 좋음)
  Gap δ = L1 - L4   총 분별력        (클수록 좋음)
```

Gap β가 결정적인 이유: Top-K 검색에서 의역(L2)이 다른 주제(L3)보다 항상 위에 올라야 NPC 기억 검색이 정확하다. β가 작으면 "혈교" 쿼리에 "소연의 시장 기억"이 상위에 섞여 들어온다.

### 2.3 교차 언어 배제의 필요성

v1.0의 전체 혼합 분석에서는 KO↔EN, KO↔ZH 교차 언어 쌍이 전체 평균에 포함되어, 교차 언어에 약한 모델의 점수가 인위적으로 낮아지고 교차 언어에 강한 모델이 실제보다 좋아 보이는 착시가 있었다. 칠국춘추가 한국어 단일 언어로 출시될 경우 교차 언어 능력은 무관하므로, [8]에서는 각 언어 내부의 쌍만 사용하여 실전 성능을 측정한다.

### 2.4 판정 기준

```
  Gap α (의역):    < 0.05 ✅  < 0.10 ⚠️  ≥ 0.10 ❌  (작을수록 좋음)
  Gap β (분리):    > 0.20 ✅  > 0.10 ⚠️  ≤ 0.10 ❌  (클수록 좋음)
  Gap γ (문맥):    > 0.05 ✅  > 0.00 ⚠️  ≤ 0.00 ❌  (양수면 좋음)
  Gap δ (총분별):  > 0.20 ✅  > 0.10 ⚠️  ≤ 0.10 ❌  (클수록 좋음)
```

| ZH β / α | 0.298 / 0.080 = 3.7x | 0.278 / 0.073 = 3.8x | C가 β/α 우위 |
| 단건 속도 | 50ms | 36ms | C가 28% 빠름 |
| 배치 건당 | 76ms | 53ms | C가 30% 빠름 |
| 파일 크기 | 605 MB | 418 MB | C가 31% 작음 |
| RAM 사용량 | ~600 MB | ~420 MB | C가 30% 절약 |
| 3언어 β 편차 | 0.008 | 0.003 | C가 더 안정적 |
| KO β 절대값 | 0.299 | 0.272 | B가 +0.027 높음 |
| KO α 절대값 | 0.082 | 0.076 | C가 의역 인식 미세 우위 |

동일한 bge-m3 모델의 양자화 수준(q8_0 vs Q4_K_M)에 따른 차이다. β/α 비율은 동률 또는 C 우위이며, 속도·크기·RAM에서 C가 28~31% 유리하다. B의 유일한 이점은 KO β 절대값이 0.027 높다는 점이나, 둘 다 ✅ 기준(>0.20)을 충족한다.

## 4. 관찰된 패턴과 분석

### 4.1 교차 언어 착시 효과

v1.0에서 e5-large(D)를 선정한 근거는 높은 그룹 내 유사도(0.86)와 교차 언어 유사도(0.84)였다. 그러나 [8]에서 KO만 독립 측정하면 D의 KO β는 0.071(❌)로 주제 분리에 실패한다.

원인은 다음과 같다. D는 KO-KO 그룹 내(0.90)와 KO-KO 교차그룹(0.81)의 차이가 0.09에 불과하다. 전체 혼합 분석에서는 KO↔EN, KO↔ZH 교차 언어 쌍이 포함되면서, 교차 언어에 약한 모델(B, C)의 교차그룹 평균이 인위적으로 낮아졌고 분리력이 있는 것처럼 보였다. 반대로 D처럼 교차 언어가 강한 모델은 교차그룹 점수도 같이 높아져 분리력 부족이 가려졌다.

A(e5-small)도 동일한 패턴으로 KO β=0.068(❌)이다. E5 계열은 한국어 단일 환경에서 혈교 이야기와 소연 이야기를 구분하지 못한다.

### 4.2 α-β 트레이드오프

10개 모델의 데이터에서 일관되게 관찰된다. α가 작은 모델은 β도 작고, β가 큰 모델은 α도 크다. 이것은 임베딩 공간의 구조적 특성이다.

α가 작다(의역을 원문과 거의 같은 점수로 매칭)는 것은 임베딩 공간이 "압축"되어 모든 것이 가까이 위치한다는 의미다. 결과적으로 다른 주제와의 거리(β)도 줄어든다. 반대로 β가 크다(다른 주제를 멀리 밀어냄)는 것은 공간이 "확산"되어 의역도 원문에서 다소 멀어진다(α 증가).

```
  압축형: A, D    — α 작음 + β 작음 → 의역 매칭은 강하지만 주제 분리 불가
  확산형: B, C, F', G' — α 큼 + β 큼 → 주제 분리 확실하지만 의역 절대 점수 낮음
  중간형: H, H'   — 중간 α + 중간 β → 타협점
```

Top-K 검색에서는 절대 점수가 아니라 상대 순위가 중요하므로, β가 충분히 크면 α가 다소 커도 의역(L2)이 다른 주제(L3)보다 항상 상위에 위치하여 검색 정확도가 유지된다.

### 4.3 언어별 성능 패턴

모든 모델이 EN에서 가장 좋은 성능을 보인다. 대부분의 임베딩 모델이 영어 코퍼스 위주로 학습되었기 때문이다. KO와 ZH는 비슷한 수준이며, ZH가 근소하게 높은 경우가 많다(중국어 학습 데이터가 한국어보다 풍부하기 때문으로 추정).

Gemma 계열은 EN에서 특히 강하다(G' EN β=0.360, 전체 최고). 그러나 KO에서는 G' α=0.111(❌), F' α=0.100(⚠️ 경계)으로 한국어 의역 인식이 상대적으로 약하다.

### 4.4 Task Prompt 효과

EmbeddingGemma에 `"task: search result | query: "` 접두어를 적용하면 β가 유의미하게 증가한다. F→F': +0.096, G→G': +0.086, H→H': +0.095 (KO β 기준). 동시에 α도 증가하고 속도가 50~60% 느려지는 트레이드오프가 있다.

### 4.5 γ (세계관 문맥 인식)의 한계

모든 모델이 KO γ에서 음수 또는 0 근처 값을 보인다. 이는 "같은 무협 세계관이지만 다른 주제"(L3)와 "완전히 다른 도메인"(L4)을 구분하지 못한다는 뜻이다. 한국어 무협 용어의 특수성 때문으로 보이며, 실전에서는 β가 충분히 크면 γ가 약해도 Top-K 검색 정확도에 영향이 없다.

### 4.6 CPU 전용 운용

벤치마크 전체가 n_gpu_layers=0(CPU 전용)으로 실행되었다. 가장 느린 B(50ms)도 NPC LLM 응답(500~3000ms) 대기 시간 안에 완료되므로, 임베딩이 UX 병목이 되지 않는다. GPU VRAM(8GB)을 NPC LLM(gemma3:12b, 7.6GB)에 전부 할당하고 임베딩은 CPU에서 실행하는 아키텍처가 합리적이다.

```
  시스템 RAM:  임베딩 모델 (420~600MB) + LanceDB + Bevy ECS
  GPU VRAM:    gemma3:12b Q4_K_M (7.6GB) 전용
```

## 5. 최종 선정: F' (embeddinggemma-300m-qat-Q8_0 + task prompt)

### 5.1 선정 근거

v2.0에서 결론을 보류했던 이유는 threshold_analyzer 벤치마크(Step 3.3)를 통해 실전 검색 정확도를 추가 검증해야 했기 때문이다. Step 3.3 완료 후 F'를 최종 선정했다.

| 기준 | F' 결과 | 판정 |
|------|---------|------|
| KO β (주제 분리) | 0.285 (✅ >0.20) | 혈교/소연/무공 주제 확실히 분리 |
| 3언어 β 편차 | 0.028 | 안정적 다국어 성능 |
| L4 역전 건수 | 0/24 (3개 언어) | 무관한 기억이 관련 기억을 역전하지 않음 |
| KO GAP (L2_min - L3_max) | +0.0660 | 충분한 안전 마진 |
| 벡터 차원 | 768 (bge-m3 대비 25% 절약) | LanceDB 저장/검색 효율 |
| 단건 속도 | 28ms (CPU) | 실시간 요구사항 충족 |

### 5.2 설정 파일 반영

선정 결과는 `assets/ai/embedding.toml`에 기록되었다. 언어별 threshold는 Step 3.3 벤치마크의 L2_min 값을 사용한다.

```
  model.name = "embeddinggemma-300m-qat-Q8_0"
  model.dimension = 768
  model.task_prompt = "task: search result | query: "
  threshold.KO = 0.4656
  threshold.EN = 0.4580
  threshold.ZH = 0.4668
```
