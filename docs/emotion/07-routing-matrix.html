OCC 상황값 → 18감정 라우팅

작가는 감정 종류를 직접 지목하지 않는다. OCC 상황값을 입력하면 엔진이 그 조합을 18개 직접 생성 감정으로 라우팅한다. 먼저 OCC 상황값이 무엇인지, 그 다음 그것이 어떻게 감정으로 변환되는지 정리한다.

1OCC 상황값 — 작가가 채우는 입력

작가가 Scene Focus 또는 AppraiseRequest의 SituationInput에 채우는 값. 세 가지 요소로 구성된다.

요소의미값
종류어느 입력 분기에 값을 넣는가event / action / object
부호그 값이 양수인가 음수인가 — 감정 쌍의 방향+ / −
분기 입력세부 감정을 가르는 보조 입력prospect / agent_id / other

실제 수치 필드는 분기별로 다르다. 모두 f32 (−1.0 ~ +1.0).

종류수치 필드분기 입력
eventdesirability_for_selfprospect, other
actionpraiseworthinessagent_id
objectappealingness(없음)

2감정 발생 — 라우팅

위 세 요소의 조합이 감정 종류를 결정한다. 작가는 "Joy를 0.8로"라고 쓸 수 없다. "종류=event, 부호=+, 분기 입력 없음"을 입력하면 엔진이 Joy로 변환한다. 작가가 적는 것은 상황의 수치, 감정 종류는 엔진의 출력이다.

라우팅 선택자 감정 종류 = OCC 상황값( 종류 · 부호 +/− · 분기 입력[전망 / 타인 영향 / 행위자 자기·타인] )

강도는 별도로 계산된다(보편 공식, HEXACO·관계 문서). 이 문서는 종류 결정만 다룬다.

3예시 — 한 Focus에 모두 입력

"focus": {
  "id": "poisoned",
  "event": {                                  // 종류=event
    "desirability_for_self": -0.7,        // 부호 − , 분기 입력 없음 → Distress
    "other": { "target_id": "ally", "desirability": 0.6 }
                                              // 분기 입력 = 타인 영향, 부호 + → HappyFor & Resentment
  },
  "action": {                                 // 종류=action
    "agent_id": "betrayer",                   // 분기 입력 = 행위자 타인
    "praiseworthiness": -0.8             // 부호 − → Reproach
  },
  "object": {                                 // 종류=object
    "target_id": "poison", "appealingness": -0.9  // 부호 − → Hate
  }
}
입력 → Distress · HappyFor · Resentment · Reproach · Hate 5감정 라우팅 action & event 동시 → Anger 자동 (복합)

전망(prospect)이 있는 경우 — 같은 event 종류라도 분기 입력에 따라 다른 감정으로 라우팅된다.

// (1) 닥쳐올 위협 — 아직 일어나지 않음
"event": {                                    // 종류=event
  "desirability_for_self": -0.8,           // 부호 −
  "prospect": "anticipation"                  // 분기 입력 = 전망 → Fear
}

// (2) 그 위협이 실제로 닥침
"event": {                                    // 종류=event
  "desirability_for_self": -0.8,           // 부호 무시 (prospect가 종류 결정)
  "prospect": "fear_confirmed"                // 분기 입력 = 전망 → FearsConfirmed + Distress
}
(1) Fear · (2) FearsConfirmed + Distress 같은 −0.8이지만 prospect에 따라 전망 → 확인으로 라우팅이 바뀐다.

집계 — 4개 입력 → 18개 출력 event 8 + other 4 + action 4 + object 2 = 18 직접 생성. 여기에 복합 4종(Anger·Gratitude·Gratification·Remorse, action+event 동시 시 엔진 자동) = OCC 22 전부. 복합은 입력 필드가 없다 → 복합 문서.

8주의할 점 3가지

① 확인 4종은 부호가 감정을 안 고른다 add_confirmation은 base_val.abs()를 쓰고, 감정 종류는 prospect 문자열이 전적으로 결정한다. +0.7에 fear_confirmed를 써도 FearsConfirmed가 나온다. 다만 자연 부호를 맞추는 것이 가독성상 옳다 — hope_*는 +(바람직했던 것), fear_*는 −(두려웠던 것).
② other는 한 값이 2감정을 동시 발생 부호가 +이면 HappyFor와 Resentment가 둘 다 계산된다(공감쌍·적대쌍 항상 평가). 생존자는 강도 단계의 성격·관계가 가른다. 또한 other를 쓰면 target_id의 관계 정보가 필수 — 없으면 InvalidSituation 에러로 거부된다.
③ 18개를 18번 설정하는 것이 아니다 Scene Focus 하나에 event/action/object + prospect/agent_id/other를 채우면 그 조합으로 감정이 자동 라우팅된다. 작가는 감정을 지목하지 않고 상황값을 입력한다.
