## 1. 개요

> "사람의 신념은 어떻게 바뀌는가"

신조(creed)는 ②층 3축 가치관의 **방향**을 결정하는 텍스트다.
같은 수치(강도)라도 신조가 다르면 완전히 다른 인물이 된다.
신조의 변화는 NPC의 정체성이 바뀌는 것이므로, 가장 신중하게 설계해야 한다.

---

## 2. 변화의 세 겹

```
  ① 강도 변화 = 흔들림 (자주, Tier 1~2)
     옳음 90 → 80
     "원칙이 약해졌다" — 같은 방향, 약해진 힘

  ② 뉘앙스 변화 = 색채 변화 (가끔, Tier 2)
     "받은 은혜는 갚는다" → "갚아야 하나... 방법이 문제다"
     핵심 의미 유지, 미세한 톤 변화. LLM이 처리.

  ③ 신조 전환 = 방향 변경 (드묾, Tier 3~4)
     "받은 은혜는 갚는다" → "지금 살아있는 것이 중요하다"
     인생에서 몇 번 안 일어난다. 일어나면 그 사람이 달라진다.
```

```
  빈도:    ① >> ② >> ③
  영향:    ① << ② << ③
  Tier:    ①=Tier1~2  ②=Tier2  ③=Tier3~4
  처리:    ①=코드+LLM  ②=LLM   ③=LLM+코드검증
```

## 3. 전환 조건 (세 가지 동시 충족)

신조가 **전환**되려면 세 가지 조건이 모두 갖춰져야 한다.

```
  ① 기존 신조의 실패 경험
     "내 원칙대로 했는데 결과가 참혹했다"
     → 강도 하락이 선행되어야 함

  ② 대안 신조와의 접촉
     "다른 원칙으로 사는 사람을 만났다"
     → creed_candidates에 대안이 등록되어 있어야 함

  ③ 선택의 순간
     "이 상황에서 기존 원칙을 따를 것인가, 새 원칙을 따를 것인가"
     → 기획된 이벤트 또는 NPC AI 자율 판단

  ①만 있으면: 흔들림 (강도만 변화)
  ①+②: 갈등 (방향이 흔들리기 시작)
  ①+②+③: 전환 가능
```

## 4. 대안 후보 시스템

```
  CreedCandidate {
      text: String,           // "놓아버리는 것도 답이다"
      source: String,         // "진야림과의 대화"
      exposure_count: u32,    // 접촉 횟수
      resonance: f32,         // 공명도 0~100
  }

  등록 조건: 다른 신조를 가진 NPC와 의미있는 상호작용
  전환 가능 조건: exposure_count >= 3 + 기존 강도 < 50
  전환 확률: 기존 강도 30 이하면 확률 증가, 80 이상이면 감소
```

### 4.1 대안 후보 등록 흐름

```
  NPC-A (신조: "은혜는 갚는다")
    ↕ 의미있는 대화/사건
  NPC-B (신조: "놓아버리는 것도 답이다")

  → 코드가 자동 판단:
    1. 두 NPC의 신조가 같은 축(옳음)에 대한 것인가?
    2. 방향이 다른가?
    3. 상호작용이 의미있는 수준인가? (importance >= 5.0)
  → 조건 충족 시 NPC-A의 creed_candidates에 등록

  이후 접촉할 때마다:
    exposure_count += 1
    resonance = LLM이 "이 대안이 얼마나 공감되는가" 판단 (0~100)
```

### 4.2 전환 판단 (코드 + LLM 협업)

```rust
fn can_transition_creed(axis: &ValueAxis, candidate: &CreedCandidate) -> bool {
    // 코드가 전제조건 확인
    let intensity_low_enough = axis.intensity < 50.0;
    let enough_exposure = candidate.exposure_count >= 3;
    let tier_allowed = current_tier >= Tier3;

    // 전제조건 불충족 시 전환 불가 (LLM에게 묻지도 않음)
    intensity_low_enough && enough_exposure && tier_allowed
}

// 전제조건 충족 시 → LLM에게 전환 여부 질문
// LLM이 "전환한다" 판단 시 → 코드가 실행
// LLM이 "아직 아니다" 판단 시 → resonance만 갱신
```

## 5. 설계 방식: 하이브리드

```
  · 핵심 전환점 → 기획자가 설계 (시나리오 이벤트)
    결과 신조도 기획자가 작성

  · 일상 뉘앙스 → LLM이 미세 조정
    "받은 은혜는 갚는다"가 경험을 거치며 톤이 변하는 것

  · NPC 자율 전환 → AI 판단 + 시스템 규칙
    대안 후보 등록/접촉/전환을 시스템이 관리
    구체적 판단은 LLM이 성찰 시 수행
```

### 5.1 세 방식의 역할 분담

```
  ┌──────────────┬──────────────────┬────────────────────┐
  │              │ 기획자 설계       │ LLM 자율           │
  ├──────────────┼──────────────────┼────────────────────┤
  │ 언제         │ 핵심 전환점      │ 일상 + 자율 전환점 │
  │ 결과 품질    │ 높음 (검증됨)    │ 중간 (변동 있음)   │
  │ 다양성       │ 낮음 (고정)      │ 높음 (매번 다름)   │
  │ 비용         │ 기획 시간        │ LLM 호출 비용      │
  │ 용도         │ 메인 스토리 분기 │ 자유 탐색/서브 루트│
  └──────────────┴──────────────────┴────────────────────┘
```

## 6. 예시: 소연의 옳음 변화 타임라인

```
  게임 시작:
  옳음 70: "받은 은혜는 반드시 갚는다" ← 기획자 설정

  중반 일상 (Tier 2 반복):
  옳음 65: "받은 은혜는 갚아야 한다... 방법이 문제다"
  ← LLM 뉘앙스 변화

  진야림과 대화 (대안 접촉):
  candidate 등록: "놓아버리는 것도 답이다"
  ← 시스템 자동 등록

  전환점 이벤트 (조고 추격 vs 사부 위독):
  플레이어 선택 → 기획자 설계 3갈래

  A. 조고를 쫓는다 → 옳음 80 "받은 은혜는 피로 갚는다"
  B. 사부에게 돌아간다 → 옳음 70 "갚는다는 건 지키는 것"
  C. 놓아버린다 (조건: 진야림 루트) → 옳음 50 "지금이 중요하다"
```

### 6.1 타임라인에서 세 겹 변화 식별

```
  ① 강도 변화: 70 → 65 (일상에서 자연스럽게)
  ② 뉘앙스 변화: "반드시 갚는다" → "갚아야 한다... 방법이 문제다"
  ③ 신조 전환: C루트에서 "갚는다" → "지금이 중요하다" (방향 자체가 바뀜)

  C루트 전환 조건 확인:
  ✅ ① 실패 경험: 강도 65로 하락 (흔들림 선행)
  ✅ ② 대안 접촉: 진야림 루트에서 candidate 등록 완료
  ✅ ③ 선택의 순간: 전환점 이벤트 발생
  → 세 조건 충족 → 전환 가능
```
