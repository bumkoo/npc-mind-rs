OCC · Event 분기

"누군가에게 무슨 일이 일어남." 3개 분기 중 가장 복잡하다 — 자기 복지, 타인의 운, 전망의 3개 하위 시스템을 품으며, prospect 필드가 전체 흐름을 가로챈다.

1입력 설정값 — EventFocus

domain/emotion/situation.rs · struct EventFocus

필드타입의미비고
desirability_for_selff32나에게 좋은가/나쁜가 (−1~1)필수
desirability_for_otherOption<…>제3자에게 좋은가/나쁜가대상 ID·관계 배율 포함
prospectOption<…>전망 정보Anticipation | Confirmation(result)
대상 분리 desirability_for_other는 단순 숫자가 아니라 자기만의 target_id와 관계 배율을 가진 하위 객체다. 대화 상대와 사건의 영향을 받는 사람이 다를 수 있기 때문 — "무백이 교룡과 대화 중, 소호가 비무에서 패했다"는 대화 상대(무백→교룡)와 사건 대상(무백→소호) 관계가 다르다.

2prospect별 발생 감정

prospect는 Option<Prospect> — 0층(None/Some) → 1층(Anticipation/Confirmation) → 2층(ProspectResult 4종)의 3단 중첩이다. 작가 입력으로는 최종 6종.

작가 입력 (JSON)0층1층2층발생 감정
prospect 키 생략None——d>0 Joy / d<0 Distress
"anticipation"SomeAnticipation—d>0 Hope / d<0 Fear
"hope_fulfilled"SomeConfirmationHopeFulfilledSatisfaction + Joy
"hope_unfulfilled"SomeConfirmationHopeUnfulfilledDisappointment
"fear_unrealized"SomeConfirmationFearUnrealizedRelief
"fear_confirmed"SomeConfirmationFearConfirmedFearsConfirmed + Distress

3제어 흐름 — prospect 게이트

같은 입력이라도 prospect 값과 조기 종료(return)·흘러내림(fall-through)에 따라 결과가 갈린다.

입력: d = desirability_for_self, prospect, desirability_for_other prospect == Confirmation(result) ? ├─ 예 → Satisfaction / Disappointment / Relief / FearsConfirmed 생성 │ result == HopeUnfulfilled | FearUnrealized ? (= 사건 안 일어남) │ ├─ 예 → 끝 · 확인 감정만 (Joy/Distress 안 만듦) │ └─ 아니오 (HopeFulfilled|FearConfirmed = 실제 발생) → 아래로 흘러내림 prospect == Anticipation ? ├─ 예 → Hope(d>0) / Fear(d<0) 생성 · 끝 · Hope/Fear만 (그 외 감정 안 만듦) └─ (전망 없음 또는 위에서 흘러내려옴) → Joy(d>0) / Distress(d<0) → desirability_for_other 있으면 Fortune-of-others 추가

4생성 감정 · 강도

조건생성 감정 (부호)강도 공식
ConfirmationSatisfaction / Disappointment / Relief / FearsConfirmed|d| × confirmation_weight
Anticipationd>0 Hope / d<0 Fear|d| × prospect_weight × 1.0
Well-beingd>0 Joy / d<0 Distress|d| × self_weight × 1.0
Fortune · 공감쌍do>0 HappyFor / do<0 Pity|do| × empathy_weight × empathy_modifier
Fortune · 적대쌍do>0 Resentment / do<0 Gloating|do| × hostility_weight × hostility_modifier
핵심 비대칭 Confirmation에서 HopeFulfilled / FearConfirmed는 사건이 실제로 일어난 경우라서 확인 감정(Satisfaction/FearsConfirmed)을 만든 뒤 fall-through하여 Joy/Distress까지 동시 생성한다. 반면 HopeUnfulfilled / FearUnrealized는 일어나지 않았으므로 확인 감정만 만들고 즉시 종료.

DesirabilityForOther 구조와 Fortune-of-others 산출

작가 입력 EventOtherInput은 2필드(target_id, desirability)지만, EventInput::into_domain이 변환 시 그 target_id와의 관계 배율을 추가해 도메인 구조 DesirabilityForOther(3필드)로 만든다. 관계 정보가 없으면 InvalidSituation 에러로 거부된다.

필드타입누가 채움
target_idString작가 입력에서 복사
desirabilityf32 (do)작가 입력에서 복사
modifiersRelationshipModifiers엔진이 target_id 관계에서 산출

event.rs의 appraise는 사건이 실제 발생한 경우(전망 없음 또는 흘러내림)에만 이 구조로 Fortune-of-others를 만든다. do 한 값으로 공감쌍·적대쌍을 동시에 평가하며, modifiers의 두 배율이 각 쌍에 따로 곱해진다:

쌍생성 감정 (부호)강도
공감쌍do>0 HappyFor / do<0 Pity|do| × empathy_weight × modifiers.empathy_modifier
적대쌍do>0 Resentment / do<0 Gloating|do| × hostility_weight × modifiers.hostility_modifier
대상 분리 두 쌍은 항상 같이 계산되며, 어느 쪽이 살아남는지는 weight(성격)와 modifier(관계)가 가른다. modifiers의 값은 사건 대상(target_id)과의 관계에서 나온 것이지 대화 상대 관계가 아니다 — 대화 상대와 사건 영향 대상이 다를 수 있기 때문이다.

5무협 워크드 예시

weight=1.0(중립 성격), modifier=1.0(중립 관계) 가정. 실제 weight·modifier는 05·06 문서 참조.

경로 A — prospect 없음 · 곽정이 무공 비급을 얻다

그냥 일어난 일. d = +0.8, prospect=None

Joy = |+0.8| × 1.0 × 1.0 = 0.80
경로 B — Anticipation · 금나라 대군이 곧 양양성을 친다

d = −0.7, prospect=Anticipation

Fear = |−0.7| × 1.0 × 1.0 = 0.70 // return — Distress·Fortune-of-others 전부 미생성 (아직 벌어지지 않음)
경로 C — Confirmation · 두려워하던 황약사의 진노가 끝내 닥치지 않았다

prospect=Confirmation(FearUnrealized)

Relief = |d| × confirmation_weight = 생성 // return — Distress 없음 (나쁜 일이 안 일어남)
경로 D — fall-through · 두려워하던 매초풍의 습격이 진짜로 들이닥쳤다

d = −0.8, prospect=Confirmation(FearConfirmed)

① FearsConfirmed = 0.8 × confirmation_weight // return 안 함 ② 흘러내림 → Distress = 0.8 × self_weight → 두 감정 동시

한 사건에서 "올 것이 왔다"(FearsConfirmed)와 "실제로 아프다"(Distress)가 동시에 깔린다.

Fortune-of-others — 미워하는 자에게 경사가 났다

공감쌍·적대쌍이 항상 같이 계산되며, 관계 배율이 어느 쪽을 살릴지 가른다.

do = +0.9 (좋은 일) · 적대 관계 (hostility_modifier 큼) 공감: HappyFor = 0.9 × empathy_weight × 작은 emp_mod → 미미 적대: Resentment = 0.9 × hostility_weight × 큰 hos_mod → 지배
설계 책임 분리 엔진은 어떤 Hope가 어떤 Confirmation으로 이어지는지 추적하지 않는다. 게임 시스템이 "이 확인은 아까 그 Hope의 결과"라 판단해 ProspectResult를 넣어주면, 엔진은 그 enum만 보고 감정 종류를 고른다. 전망 시퀀스 연결은 게임의 책임, 엔진은 순수 함수.

6실제 코드

▸ appraisal/event.rs — appraise() domain/emotion/appraisal/event.rs 
pub fn appraise<P: AppraisalWeights>(p: &P, state: &mut EmotionState, event: &EventFocus) {
    let d = event.desirability_for_self;
    let ctx = &event.description;

    // 1. 전망 확인 (Satisfaction, Disappointment, Relief, FearsConfirmed)
    if let Some(Prospect::Confirmation(result)) = &event.prospect {
        let w = p.desirability_confirmation_weight(d);
        add_confirmation(state, result, d, w, ctx);
        match result {
            ProspectResult::HopeUnfulfilled | ProspectResult::FearUnrealized => return,
            _ => {} // HopeFulfilled, FearConfirmed → 아래 Joy/Distress 계속
        }
    }

    // 2. 미래 전망 (Hope, Fear)
    if let Some(Prospect::Anticipation) = &event.prospect {
        let w = p.desirability_prospect_weight(d);
        add_valence(state, EmotionType::Hope, EmotionType::Fear, d, w, 1.0, ctx);
        return;
    }

    // 3. 자기 복지 (Joy, Distress)
    let w = p.desirability_self_weight(d);
    add_valence(state, EmotionType::Joy, EmotionType::Distress, d, w, 1.0, ctx);

    // 4. 타인의 운 (HappyFor, Pity, Resentment, Gloating)
    if let Some(other) = &event.desirability_for_other {
        let d_other = other.desirability;
        let other_ctx = format!("{} (대상: {})", ctx, other.target_id);
        // 공감 기반 (HappyFor, Pity)
        let emp_w = p.empathy_weight(d_other);
        add_valence(state, EmotionType::HappyFor, EmotionType::Pity,
                    d_other, emp_w, other.modifiers.empathy_modifier, &other_ctx);
        // 적대 기반 (Resentment, Gloating)
        let hos_w = p.hostility_weight(d_other);
        add_valence(state, EmotionType::Resentment, EmotionType::Gloating,
                    d_other, hos_w, other.modifiers.hostility_modifier, &other_ctx);
    }
}
▸ helpers.rs — add_valence() / add_confirmation() domain/emotion/appraisal/helpers.rs 
pub fn add_valence(state: &mut EmotionState,
    pos_type: EmotionType, neg_type: EmotionType,
    base_val: f32, weight: f32, modifier: f32, ctx: &str) {
    if weight <= 0.0 { return; }              // ← 성격이 감정 원천 차단
    if base_val > 0.0 {
        let val = base_val * weight * modifier;
        state.add(Emotion::with_context(pos_type, val, ctx));
    } else if base_val < 0.0 {
        let val = base_val.abs() * weight * modifier;
        state.add(Emotion::with_context(neg_type, val, ctx));
    }
}

pub fn add_confirmation(state: &mut EmotionState,
    result: &ProspectResult, base_val: f32, weight: f32, ctx: &str) {
    let etype = match result {
        ProspectResult::HopeFulfilled  => EmotionType::Satisfaction,
        ProspectResult::HopeUnfulfilled=> EmotionType::Disappointment,
        ProspectResult::FearUnrealized => EmotionType::Relief,
        ProspectResult::FearConfirmed  => EmotionType::FearsConfirmed,
    };
    let val = base_val.abs() * weight;        // modifier 없음
    state.add(Emotion::with_context(etype, val, ctx));
}
