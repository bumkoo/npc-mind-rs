HEXACO 반영 — 성격 가중치

보편 공식 |OCC 상황값| × 성격(HEXACO 산출) × 관계에서 성격(HEXACO 산출)의 정체. 상수가 아니라 HEXACO 성격이 만드는 함수다. 같은 자극을 인물마다 다르게 느끼게 한다.

1보편 골격

7개 weight 함수가 모두 같은 골격을 쓴다. 기저값에서 출발해 성격 facet을 가감한 뒤 범위로 clamp한다. Score::effect(w) = 점수 × w.

personality.rs · finalize_weight weight = clamp( 기저값 + Σ( 성격 facet × 영향계수 ) , 범위 )

세 요소를 차례로 푼다 — 기저값(출발점), 영향계수(facet 가중), clamp 범위(상·하한).

2기저값 — weight의 출발점

기저값(base)은 성격 영향이 0일 때의 weight 출발점이다. 감정 계열마다 다른 값을 둬서 발동 난이도를 차등화한다. 모두 personality.rs의 const.

상수값적용 감정의미
BASE_SELF1.0Joy/Distress, Pride/Shame, Hope/Fear, 확인4종, Love/Hate성격 무관 기본 발동
BASE_EMPATHY0.5HappyFor/Pity타인의 운은 자기보다 약하게 시작
BASE_HOSTILITY0.0Resentment/Gloating성격이 나빠야만 발동 (정직성 높으면 0으로 잘림)

영향계수 (W_*)

성격 요인에 곱해지는 가중치. 클수록 그 요인이 weight를 크게 움직인다. 계수 크기 = 해당 감정에서 그 요인이 갖는 결정력이다.

상수값적용 감정왜 이 값인가
W_MILD0.2전망(Hope/Fear)·확인의 신중함신중함은 미래 예측에서 충격을 완만히 줄이는 보조 효과. 주효과(정서성·외향성)보다 약해야 하므로 표준보다 낮다.
W_STANDARD0.3자기 감정 전반(Joy/Distress, Pride/Shame 등), 매력도(Love/Hate)성격이 감정에 주는 일반적 영향의 기본값. 기저 1.0 대비 적당한 개인차(약 0.7~1.3)를 만든다.
W_STRONG0.4공감(HappyFor/Pity), 적대 중 원만성(Gloating)타인의 운은 기저값이 낮다(0.5/0.0). 낮은 출발점에서 성격이 발동을 좌우해야 하므로 표준보다 강하다.
W_DOMINANT0.7적대 중 정직성(Resentment)한 요인이 발동을 거의 단독으로 결정해야 할 때. → 3번 함수 표 뒤 해석 참조

clamp 범위

상수범위적용 감정차이 (하한)
CLAMP_STANDARD(0.5, 1.5)Joy/Distress, Hope/Fear, 확인4종, Pride/Shame/Admir./Reproach, Love/Hate약해도 0.5 보장 — 기본 발동
CLAMP_OPTIONAL(0.0, 1.5)HappyFor/Pity, Resentment/Gloating (타인의 운)0까지 → 미발동 가능 (하한 게이트)

상한은 둘 다 1.5 — 극단 성격도 강도 3배(0.5→1.5)를 못 넘게 폭주 방지.

37개 weight 함수

정서성·외향성·원만성·성실성·정직성·개방성(HEXACO 6요인)의 평균 또는 개별 facet을, 상황값 부호에 따라 다르게 조합한다.

왜 적대의 정직성만 0.7인가 대부분 계수는 0.3~0.4인데 hostility_weight의 Resentment만 −정직성×0.7로 가장 크다. 먼저 차단은 계수가 아니라 기저값 0.0이 처리한다 — 정직성이 0 이상이면 −정직성×계수가 0 이하가 되어 clamp 하한 0에서 잘리므로, 계수가 0.3이든 0.7이든 선한 사람은 자동으로 미발동이다.

그럼 0.7은 무엇을 정하나 — 정직성이 음수(부정직)일 때 Resentment가 얼마나 세게 발동하는지(기울기·정점)다. Resentment는 정직성 1개로만 가므로(정직성=−1.0 → 0.7), 두 요인으로 가는 Gloating(정직성=−1.0·원만성=−1.0 → 0.4+0.4=0.8)과 정점을 비슷하게 맞추려면 단일 요인 계수가 더 커야 한다. 즉 0.7은 "차단 강화"가 아니라 "악인이 Gloating과 비슷한 세기로 시기하게" 만드는 값이다.
Phase 2.4.1 예정 · 정서성 weight 재검토 desirability_self_weight·desirability_prospect_weight는 부호 분기 밖에서 정서성×0.3을 무조건 더한다 → Joy·Hope(긍정)에도 정서성이 증폭기로 작용한다.

문제: HEXACO 정서성의 facet은 두려움·불안·의존·감상성 — 전부 부정·애착 정서다. 이 코드의 facet 정의(fearfulness/anxiety/dependence/sentimentality)도 표준을 따른다. 그런데 weight에서는 정서성을 "범용 감정 반응성"으로 써서 긍정 정서까지 키운다 — facet 정의(표준)와 사용처(범용)의 내부 불일치. 긍정 정서 증폭은 외향성(활력·자존감) 영역이 맞다. Distress·Fear에 정서성이 붙는 것은 이론 부합이나, Joy·Hope에 붙는 것은 어긋난다.

적용 방향 (3단계, 침습도 순):
  1. self_weight (Joy/Distress) — 정서성 공통항을 제거하고 부정 분기로만 이동. Joy는 외향성 주도, Distress는 정서성+원만성+신중함 유지. 본문만 수정, 낮은 침습도.
  2. prospect_weight (Hope/Fear) — 정서성을 Fear 분기로 이동. 동시에 두려움 이중계산 해소 — 두 안 중 택1: (A) 정서성 평균만 쓰고 두려움 facet 추가분 제거(추적 명확·권장), (B) 두려움 강조 유지하되 추가분 가중치를 축소(0.3→0.2)해 이중 부담 완화. 게임상 두려움 개별 강조가 필요하면 B, 정합 우선이면 A.
  3. confirmation_weight (확인 4종) — 긍정 확인(Satisfaction/Relief)에도 정서성이 과한 같은 문제. 단 현재 부호 분기가 없어(.abs()로 부호 무시) 분기를 넣으려면 함수 시그니처에 prospect result를 넘겨야 함 → 침습도 높음, 별도 과제로 분리.
권장 묶음: 1·2를 함께 처리(둘 다 본문만), 3은 보류. 공통 리스크: Joy/Hope(+Satisfaction/Relief) 강도가 내려가므로 20 PAD 벤치 기대값 재측정 필수.

43가지 설계 원칙

  • 부호 분기 — 같은 입력값이라도 좋은 일/나쁜 일에서 다른 요인이 작동한다. (Joy는 외향성으로 증폭, Distress는 원만성·신중함으로 억제)
  • 하한 게이트 — empathy/hostility는 clamp 하한이 0. 성격이 감정을 원천 차단할 수 있다.
  • clamp — 표준 범위 [0.5,1.5]로 묶여, 아무리 극단 성격이라도 강도 3배(0.5→1.5)를 못 넘는다. 감정 폭주 방지.

5무협 워크드 예시

곽정 vs 양강 — 같은 −0.7 배신, 다른 Distress

곽정(원만성·신중함 높음)은 desirability_self_weight에서 나쁜 일 분기의 −원만성×0.3 −신중함×0.3이 크게 깎여 weight가 하한 0.5에 가까워진다. 양강(원만성·신중함 낮음)은 덜 깎여 weight가 높다. 같은 사건, 다른 고통.

대협은 시기하지 않는다 — hostility_weight = 0

정직성이 높으면 Resentment 식 −정직성×0.7이 음수 → 기저 0과 합쳐 clamp 하한 0 → 감정 자체가 생성 안 됨. 단위 테스트 hostility_weight_zero_for_high_honesty가 이를 박제. 곽정·임충은 시기·고소함이 구조적으로 0, 육겸·양강만 발동한다.

정직성=+1.0 → e = −1.0 × 0.7 = −0.70 weight = clamp(0.0 + (−0.70), 0.0, 1.5) = 0.0 // 미발동
겸손의 비대칭 — 같은 facet이 Pride는 깎고 Shame은 키운다

리무바이가 자기 공을 내세우지 않으면서(Pride 억제) 자책은 깊은 것(Shame 증폭)이 praiseworthiness_weight의 자기+칭찬 −겸손 / 자기+비난 +겸손 비대칭으로 모델링된다.

6실제 코드

▸ personality.rs — 상수 + Score 헬퍼 domain/personality.rs 
const W_STANDARD: f32 = 0.3;  const W_STRONG: f32 = 0.4;
const W_DOMINANT: f32 = 0.7;  const W_MILD:  f32 = 0.2;
const BASE_SELF: f32 = 1.0;  const BASE_EMPATHY: f32 = 0.5;
const BASE_HOSTILITY: f32 = 0.0;
const CLAMP_STANDARD: (f32,f32) = (0.5,1.5);
const CLAMP_OPTIONAL: (f32,f32) = (0.0,1.5);

impl Score {
    pub fn effect(&self, weight: f32) -> f32 { self.0 * weight }
}
fn finalize_weight(base: f32, effects: f32, range: (f32,f32)) -> f32 {
    (base + effects).clamp(range.0, range.1)
}
▸ impl AppraisalWeights — self / empathy / hostility / praiseworthiness domain/personality.rs 
fn desirability_self_weight(&self, d: f32) -> f32 {
    let avg = self.dimension_averages();
    let mut e = avg.e.effect(W_STANDARD);
    e += if d >= 0.0 { avg.x.effect(W_STANDARD) }
          else { -avg.a.effect(W_STANDARD)
                 - self.conscientiousness.prudence.effect(W_STANDARD) };
    finalize_weight(BASE_SELF, e, CLAMP_STANDARD)
}

fn empathy_weight(&self, d: f32) -> f32 {
    let avg = self.dimension_averages();
    let e = if d >= 0.0 { avg.h.effect(W_STRONG) + avg.a.effect(W_STRONG) }
             else { avg.a.effect(W_STRONG)
                    + self.emotionality.sentimentality.effect(W_STRONG) };
    finalize_weight(BASE_EMPATHY, e, CLAMP_OPTIONAL)
}

fn hostility_weight(&self, d: f32) -> f32 {
    let avg = self.dimension_averages();
    let e = if d >= 0.0 { -avg.h.effect(W_DOMINANT) }
             else { -avg.h.effect(W_STRONG) - avg.a.effect(W_STRONG) };
    finalize_weight(BASE_HOSTILITY, e, CLAMP_OPTIONAL)
}

fn praiseworthiness_weight(&self, is_self: bool, pw: f32) -> f32 {
    let avg = self.dimension_averages();
    let mut e = avg.c.effect(W_STANDARD);
    e += if is_self {
        if pw > 0.0 { -self.honesty_humility.modesty.effect(W_STANDARD) }
        else          {  self.honesty_humility.modesty.effect(W_STANDARD) }
    } else {
        if pw < 0.0 { -self.agreeableness.gentleness.effect(W_STANDARD) }
        else          {  self.agreeableness.gentleness.effect(W_STANDARD) }
    };
    finalize_weight(BASE_SELF, e, CLAMP_STANDARD)
}
