감정 발생 파이프라인 情感發生

성격(HEXACO)이 상황(OCC)을 해석하여 감정을 생성하고, 관계가 그 감정을 증폭·억제하며, 다시 감정이 관계를 갱신한다. 아래 문서는 현재 구현된 코드를 함수 단위로 검토해 정리한 것이다.

먼저 작가가 채운 입력 조합이 어떤 감정 종류가 만들어질지 결정한다(라우팅 — 자세히는 07 문서).

① 라우팅 선택자 · 어떤 감정이 만들어지나 감정 종류 = OCC 상황값( 종류 · 부호 +/− · 분기 입력[전망 / 타인 영향 / 행위자 자기·타인] )

그 다음 아래 보편 공식이 그 감정의 강도를 계산한다.

② 보편 공식 · 강도 산출 · helpers.rs add_valence 감정 강도(0~1) = |OCC 상황값| × 성격(HEXACO 산출) × 관계(Relationship 산출)

OCC 상황값은 작가가 부여하는 정규화 상수(−1~1)이고 부호가 감정의 종류를 가른다. 성격(HEXACO 산출)은 NPC HEXACO 점수를 가중치로 계산한 값(05), 관계(Relationship 산출)은 affinity·trust 축으로 산출한 배율(06)이다. 같은 감정이 여러 번 더해지면 EmotionState.add가 강도를 누적한 뒤 0~1로 클램프한다.

11단계 · OCC 감정 발생

상황(Situation)은 ID 없는 Value Object이며, OCC 3대 분기를 각각 Option으로 보유한다. 엔진은 순수 함수 — 상황·감정 추적은 게임 시스템의 책임이다. 각 분기를 분리해 정리했다.

01 · OCC

Event 분기

사건의 결과 — Joy/Distress, Fortune-of-others, 전망(Hope/Fear·확인 4종). prospect 게이트와 fall-through.

domain/emotion/appraisal/event.rs
 02 · OCC

Action 분기

행위자의 행동 — 자기(Pride/Shame) vs 타인(Admiration/Reproach). agent_id 정규화.

domain/emotion/appraisal/action.rs
 03 · OCC

Object 분기

대상의 존재 자체에 대한 호불호 — Love/Hate. 가장 단순한 단일 산식.

domain/emotion/appraisal/object.rs
 04 · OCC

복합 Case

Action+Event 동시 존재 시 자동 생성 — Gratitude/Anger/Gratification/Remorse. 두 감정의 평균.
