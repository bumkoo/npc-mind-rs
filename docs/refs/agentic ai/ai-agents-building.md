## 1. 에이전트 기본 아키텍처

```
    ┌──────────────────────────────────────┐
    │            AI Agent                  │
    │                                      │
    │  ┌─────────┐  ┌──────────┐  ┌─────┐ │
    │  │ LLM     │  │ Memory   │  │Tools│ │
    │  │(추론엔진)│  │(기억체계) │  │(도구)│ │
    │  └────┬────┘  └────┬─────┘  └──┬──┘ │
    │       └──────┬─────┘           │     │
    │              ▼                 │     │
    │       ┌──────────┐            │     │
    │       │ Planning │◄───────────┘     │
    │       │ (계획)    │                  │
    │       └──────────┘                  │
    └──────────────────────────────────────┘
```

### 에이전트 유형 스펙트럼
1. **정보 에이전트**: 정보 검색/요약 (최소 복잡도)
2. **행동 에이전트**: 가상/실제 세계에서 행동 수행
3. **상호작용 에이전트**: 환경과 다른 에이전트와 양방향 소통 ← **칠국춘추 NPC**

## 2. 태스크 계획 (Task Planning) 방법론

### 2.1 분해-우선 방법 (Decomposition-first)
```
전체 작업 → [하위과제1] → [하위과제2] → [하위과제3]
              (순차 해결)
```
- 장점: 전체 조망 가능, 환각/망각 감�0
- 단점: 중간 오류 수정 불가

### 2.2 교차 분해 방법 (Interleaved)
```
작업 → 하위과제1 생성 → 해결 → 하위과제2 생성 → 해결 → ...
```
- 장점: 동적 조정 가능
- 단점: 복잡한 문제에서 비용 폭증

### 2.3 칠국춘추 NPC 적용
- NPC 일상: 분해-우선 (아침 수련 → 점심 → 오후 임무 → 저녁)
- NPC 돌발 상황: 교차 분해 (전투 발생 → 즉시 재계획)

## 3. RAG (Retrieval-Augmented Generation)

```
    사용자 쿼리
         │
         ▼
    ┌──────────┐     ┌──────────────┐
    │ Embedding │────►│ Vector DB    │
    │ (임베딩)   │     │              │
    └──────────┘     │ 유사도 검색    │
                     └──────┬───────┘
                            │ Top-K 결과
                            ▼
                     ┌──────────────┐
                     │ LLM + Context│
                     │ (생성)        │
                     └──────────────┘
```

### RAG 평가 지표
- **Precision**: 가색된 문서 중 관련 문서 비율
- **Recall**: 전체 관련 문서 중 가색된 비율
- **MRR (Mean Reciprocal Rank)**: 첫 번째 관련 결과의 순위 역수 평균
- **MAP (Mean Average Precision)**: 관련 문서 발견 지점의 평귰 정밀도

### 칠국춘추 적용
- NPC 기억 저장: LanceDB에 임베딩 벡터로 저장
- NPC 기억 검색: 현재 상황 → 관련 기억 Top-K 가색 → LLM에 컨텍스트로 전달

## 4. 메모리 기반 계획 (Memory-Augmented Planning)

단기 기억과 장기 기억 분리:
- **단기 기억**: 현재 환경의 임시 변화 저장
- **장기 기억**: 중요 정보 통합 저장

```
칠국춘추 NPC 메모리 구조:

┌─ 단기 기억 (현재 대화, 진행 중인 전투 상태)
│
├─ 장기 기억 (LanceDB)
│   ├─ 관찰 기억 (일상 경험)
│   ├─ 성찰 기억 (고차 추론)
│   └─ 관계 기억 (다른 NPC/플레이어와의 관계)
│
└─ 계획 기억 (현재 일일/주간 계획)
```

## 5. 멀티에이전트 시스템 (MAS) 핵심

### 단일 에이전트 vs 멀티에이전트 비교

| 항목 | 단일 에이전트 | 멀티에이전트 |
|---|---|---|
| 비용 | 낮음 | 높음 (더 많은 LLM 호출) |
| 지연 | 낮음 | 높음 (에이전트 간 통신) |
| 장애 허용 | 낮음 | 높음 (개별 에이전트 격리) |
| 모듈성 | 단일체 | 독립적 추가/교체 가능 |
| 확장성 | 제한적 | 병렬 분산 가능 |

### MAS 실패 원인 3대 범주
1. **설계 실패**: 시스템 설계 결함
2. **에이전트 간 실패**: 통시/조정 오류
3. **단일 에이전트 실패**: 개별 에이전트의 추론 오류

### 칠국춘추 적용 판단
- 50~200 NPC → 각각이 독립 에이전트이지만, 모두가 동시에 활성화될 필요 없음
- **하이브리드 접근**: 플레이어 근처 NPC만 활성화 (단일 에이전트 수준 비용)
- 문파/조직 단위 그룹 행동 → 대표 에이전트가 계획, 나머지는 따름

## 6. 반성과 개선 (Reflection & Refinement)

```
생성 → 피드백 → 개선 → 생성 → 피드백 → 개선 → ...
```

- 에이전트가 자신의 행동을 평가하고 개선
- 칠국춘추: NPC가 전투 후 자싨의 전략을 반성하고 무공 수련 방향 조정

## 7. Local LLM 고려사항

### Fine-tuning vs RAG 비교
| 방식 | 장점 | 단점 |
|---|---|---|
| RAG | 저비용, 유연한 업데이트 | 검색 정확도 의존 |
| Fine-tuning | 지식 내재화, 빠른 추론 | 고비용, 업데이트 어려움 |

### 칠국춘추 전략
- **RAG 우선**: NPC 기억/경험은 벡터DB RAG로 처리
- **Fine-tuning 보완**: 무협풍 대화체, 장른 트유의 푘현은 Fine-tuning으로 내재화
- **하이브리드**: Fine-tuned 모델 + RAG로 최적 조합
