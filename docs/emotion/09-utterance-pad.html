08의 입력 stimulus가 어디서 오는가. Player 대사 한 줄이 임베딩 → 화자 PAD → 청자 PAD로 바뀌어 자극이 된다. 화자가 한 말 ≠ NPC가 받는 자극.

왜 청자 변환이 필요한가 Player가 "미안해"라고 하면 화자 기준 PAD는 후회(pleasure 음수). 그러나 그 말을 듣는 NPC에게는 사과를 받는 자극이라 의미가 다르다. 화자 PAD를 그대로 쓰면 감정이 거꾸로 움직인다. 그래서 변환 단계가 필수.

2.0 약자 먼저 읽기

식에 나오는 P_L, P_S 같은 기호부터 푼다. 대문자는 축, 아래첨자는 누구의 값인가를 가리킨다.

기호뜻설명
PPleasure쾌·불쾌 (기분이 좋은가 나쁜가)
AArousal각성 (얼마나 흥분·고조되었나)
DDominance지배·통제 (기세가 위에 있나 눌렸나)
_SSpeaker · 화자말을 한 사람 (Player)
_LListener · 청자말을 듣는 NPC
읽는 법 P_S = 화자의 쾌·불쾌(대사에서 측정한 값) · P_L = 그 말을 받은 청자(NPC)가 느끼는 쾌·불쾌 — 우리가 구하려는 결과. A_S→A_L, D_S→D_L도 같은 방식.

2.1 변환식

화자 PAD → 청자 PAD P_L = sign × coef_p[mag] × P_S
A_L = coef_a[mag] × A_S
D_L = coef_d[mag] × D_S

한 줄로 읽으면 — "화자가 드러낸 PAD에 방향(sign)과 세기(coef)를 적용해 청자가 받는 PAD로 옮긴다." P축만 방향을 뒤집을 수 있고, A·D축은 세기만 조절한다.

2.2 세 개의 손잡이

변환은 손잡이 세 개로 이뤄진다. 각각이 무슨 일을 하는지가 핵심이다.

손잡이역할비유적용 축
sign방향 그대로(+1) / 뒤집기(−1)방향 스위치P축만
mag약·보통·강 중 하나 선택세기 다이얼계수표 행 결정
coef_*[mag]실제로 곱하는 수증폭/감쇠 배율P·A·D 각각

출처 — sign은 SignClassifier, mag은 MagnitudeClassifier (둘 다 의미 비교 기반 분류기), coef는 MagnitudeCoefTable(튜닝 가능한 계수표). P_S/A_S/D_S는 UtteranceAnalyzer가 대사에서 산출.

2.3 sign — SignClassifier가 정하는 법

sign은 한 가지 질문에 답한다 — "이 말을 들으면 청자 기분은 화자와 같은 방향인가, 반대 방향인가?"

판정값대표 표현흐름
Keep+1감사·칭찬 "고맙소"화자 P+ → 청자 P+ (그대로)
Invert−1사과·애원 "미안하오"화자 P− → 청자 P+ (뒤집힘)

판정 방법(개념) — 미리 모아둔 예문 두 묶음(Keep 예문: 감사·칭찬 / Invert 예문: 사과·애원)을 준비해두고, 입력 대사를 두 묶음과 의미적으로 비교해 더 닮은 쪽으로 분류한다. 닮은 정도의 차이(margin)가 크면 확신, 비슷하면 애매한 판정이다.

애매하면 Keep 두 묶음 점수가 동점이면 Keep(+1, 안 뒤집음)이 기본값. 잘못 뒤집는 쪽이 안 뒤집는 쪽보다 더 위험하므로 보수적으로 둔다.

2.4 왜 A·D축은 방향을 안 건드리나

P축만 부호 반전 각성(A)·지배(D)는 화자·청자가 대체로 같은 방향이다 — 흥분은 전염되고(A), 기세는 그대로 전달된다(D). 그래서 강도 계수만 곱한다. 오직 P(쾌·불쾌)만 "미안해 문제"(화자 후회 → 청자 안도) 때문에 방향 반전이 필요하다.
다음 단계 예고 이 "A·D는 부호 고정" 가정이 개선 논의의 출발점이다. 반어("허허, 훌륭하시오")는 D도 같이 뒤집혀야 하고, 지배는 상보적(화자 D↑ → 청자 위축 또는 반발)이라 단순 복사가 한계를 가진다 — 다음 섹션에서 다룬다.

32경로 — Prefilter 우선

converter.rs · convert()

대사 텍스트 │ Prefilter 정규식 매칭? (예: "^(허허|아이고)" → 빈정) ├─ hit → 카테고리의 sign·magnitude·p_s_default 즉시 사용 │ (분류기 건너뜀, P_S는 p_s_default로 대체) └─ miss → SignClassifier + MagnitudeClassifier (임베딩 k-NN) → sign·magnitude 추론
Prefilter가 먼저인 이유 "허허", "아이고" 같은 빈정·반어 표현은 임베딩 의미만으로는 부호를 자주 틀린다. 정규식으로 먼저 잡아 카테고리 고정값을 쓰면 분류기 오류를 우회. Prefilter hit 시 p_s_default가 화자 P를 대체(빈정은 화자 표면 PAD 신뢰 불가).

3.1 hit 시 가져오는 세 값

카테고리에는 분류기 대신 쓸 고정값 3개가 미리 적혀 있다. 정규식이 매칭되면 이 값들을 즉시 쓴다(분류기 호출 안 함).

[[category]]
name = "sarcasm_interjection"
sign = "invert"        # → −1
magnitude = "strong"   # → 강 계수 행
p_s_default = 0.6      # → P_S 대체값
patterns = ["^(허허|아이고)"]
값역할
signKeep/Invert를 분류기 대신 카테고리가 지정 (예: invert = −1)
magnitude약/보통/강 지정 → coef 테이블 행 선택 (예: strong)
p_s_default화자 P를 무시하고 이 값으로 대체 — 반어는 화자 표면 PAD를 신뢰 불가
두 경로의 핵심 차이 = P_S 분류기 경로는 화자 실제 pleasure(speaker_pad.pleasure)를 쓰지만, prefilter 경로는 그걸 버리고 p_s_default로 덮어쓴다. sign·magnitude도 분류기보다 정규식 판정을 우선.
p_s = p_s_override.unwrap_or(speaker_pad.pleasure) — prefilter면 Some(0.6), 분류기면 화자 실제값.

4무협 워크드 예시

분류기 경로 — Player가 진심 어린 칭찬

임베딩이 sign_keep 프로토타입에 근접 → sign=Keep(+1). magnitude=normal. 화자 PAD P_S=+0.4

P_L = +1 × coef_p[normal] × 0.4 = 양수 (칭찬 → NPC 쾌) A_L = coef_a[normal] × A_S · D_L = coef_d[normal] × D_S
Prefilter 경로 — "허허, 참 훌륭하시오" (반어)

정규식 ^(허허) hit → 카테고리 sarcasm: sign=Invert(−1), mag=strong, p_s_default=0.6

P_L = −1 × coef_p[strong] × 0.6 = 음수 (표면은 칭찬, 실제 NPC엔 모욕) // 화자 표면 P 무시, p_s_default 사용 — 반어라 표면 신뢰 불가

5실패 시 fallback

converter.rs · convert_or_fallback()

converter 미주입이거나 임베딩 부재거나 변환 실패 시 — 화자 PAD를 그대로 반환(passthrough). 변환 실패는 tracing::warn! 남기고 silent failure 방지. DialogueOrchestrator·Mind Studio가 동일 분기를 갖던 drift를 이 도메인 헬퍼 하나로 통합.

6그 다음 — 자극 PAD는 08로

2~5에서 만든 청자 PAD는 곧 자극 PAD가 되어 08로 넘어간다. 08의 apply_stimulus가 NPC의 활성 감정마다 pad_dot(감정 PAD, 자극 PAD)로 공명을 계산해 강도를 ↑/↓한다 — 공식·D 격차 배율의 상세는 08 PAD 자극 경로 참조.

비교 대상이 다르다 (개선 설계 시 주의) 09는 화자 vs 청자를 본다. 08 pad_dot은 NPC 현재 감정 vs 자극을 본다. 둘 다 D를 다루지만 대상이 다르므로, D 상보성을 09에 또 넣으면 08의 격차 배율과 이중 적용될 수 있다.

7.3 권장 — A 우선

A부터, B는 보류 A는 시그니처를 안 건드려 prefilter·fallback 구조를 그대로 둔 채 얹을 수 있다. B의 "청자 현재 D 반영"은 사실 08 pad_dot의 D 격차 배율과 겹친다(§6 참조) — 09에 또 넣으면 이중 적용. 그래서 09는 "발화 자체의 D 방향"(반어 등)만 책임지고, "NPC 상태와의 D 격차"는 이미 작동하는 08에 맡기는 분담이 깔끔하다.
경계 A 적용 시에도 D_sign은 발화 의미상의 반전(반어)만 다룬다. 청자의 현재 기세와의 격차(위축/반발)는 08 pad_dot 소관 — 09에서 재현하지 않는다.

fn build_result(&self, sign: Sign, magnitude: Magnitude,
    speaker_pad: &Pad, p_s_override: Option<f32>, path: ConvertPath) -> ConvertResult {
    let p_coef = self.coef_table.p_coef(magnitude);
    let a_coef = self.coef_table.a_coef(magnitude);
    let d_coef = self.coef_table.d_coef(magnitude);

    let p_s = p_s_override.unwrap_or(speaker_pad.pleasure);

    let listener_pad = Pad::new(
        sign.as_f32() * p_coef * p_s,    // P축: 부호 반전 가능
        a_coef * speaker_pad.arousal,      // A축: 계수만
        d_coef * speaker_pad.dominance,    // D축: 계수만
    );
    // ... meta 생성 ...
}
▸ converter.rs — convert() 2경로 domain/listener_perspective/converter.rs 
fn convert(&self, utterance: &str,
    speaker_pad: &Pad, utterance_embedding: &[f32]) -> Result<ConvertResult, _> {
    // 1. Prefilter 먼저
    if let Some(hit) = self.prefilter.classify(utterance) {
        return Ok(self.build_result(hit.sign, hit.magnitude,
            speaker_pad, Some(hit.p_s_default), path));   // p_s_default 사용
    }
    // 2. Classifier 경로 (k-NN)
    let sign_result = self.sign_classifier.classify(utterance_embedding);
    let mag_result = self.magnitude_classifier.classify(utterance_embedding);
    Ok(self.build_result(sign_result.predicted, mag_result.predicted,
        speaker_pad, None, path))            // speaker_pad.pleasure 사용
}
▸ converter.rs — convert_or_fallback() domain/listener_perspective/converter.rs 
pub fn convert_or_fallback(
    converter: Option<&dyn ListenerPerspectiveConverter>,
    utterance: &str, speaker_pad: Pad, embedding: Option<&[f32]>) -> Pad {
    let (Some(converter), Some(emb)) = (converter, embedding) else {
        return speaker_pad;          // 입력 부족 → passthrough
    };
    match converter.convert(utterance, &speaker_pad, emb) {
        Ok(result) => result.listener_pad,
        Err(e) => { tracing::warn!(...); speaker_pad }  // 실패 → 화자 PAD
    }
}
